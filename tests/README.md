# tests

What a change must pass is [checks per change](../docs/designs/fleet-delivery-pipeline.md#checks-per-change): `scripts/check.sh` (`pnpm run check`), the same in CI and locally. A worker adds a test only when its task asks for one.

* `trial/slice.test.ts`: the smoke. `node tests/trial/run.ts` starts the real coordinator (`go/bin/fleet-coordinator`, build first) on a fresh database of the machine's test PostgreSQL (`harness.ts`) and runs 11 checks over HTTP and SSE: browser and host credentials, a session and its execution, the host poll, receipts, events, the stream with resume, row-level visibility and concurrent writes. The `go` job of CI runs it on every change.
* `harness.ts`: starts the coordinator on a fresh database with the PDS18 roles; `s3-fake.ts` is a fake object store.
* `fixtures/projects/`: the projects `hello-world` and `hello-world-alt` the coordinator under test serves. No deployment ships them: `harness.ts` (`testConfig`) and the Go tests (`testConfigDir`) add them to a fresh copy of `config/`.
* `ui/*.test.ts`: pure unit tests of the app and `packages/ui`, no browser and no coordinator; the `app` job runs them (`node --test tests/ui/*.test.ts`, about a second). `ui/design-rules.test.ts` checks the UI design rules (S9).
* `ui/app.check.ts`, `ui/scroll.check.mjs`, `ui/ux.check.mjs`, `ui/layout-break.check.mjs`, `ui/trace.check.mjs` (with `layout.check.ts`, `seed.ts`, `home-card.ts`): the browser parts of the design report (`pnpm run check:design`, the warning-only `reports` job). They never gate.
* `ui/mirror.check.ts`: the read mirror and the shell's person check and idle update ([app source](../app/src/README.md#verification)): a reload renders before any read answers, reads each thing once, keeps another person's mirror hidden and keeps the page when the person check fails; the app update waits for the person to come back. Run by hand or in a pull request's proof; it exits 1 on a failed claim.
* `journeys/walk.ts`: read-only walk of journeys J1–J5 ([journeys](../docs/designs/fleet-ia-and-journeys.md#3-core-user-journeys-j1j5)) on the deployed app as `site-agents`. Prints a Markdown report and always exits 0; it stops before every write. `scripts/watch-landings.sh` runs it after a landing reaches hosts or the site; `node tests/journeys/walk.ts` runs it alone.
* [`performance/`](performance/README.md): synthetic interface fixtures and an isolated coordinator, PostgreSQL and Chromium workload driver for capacity measurements by hand. Not in CI.
* `trial/arms/`, `trial/measure.ts`: the stack trial's measurement tools ([stack trial](../docs/designs/fleet-stack-trial.md)). Not in CI.
