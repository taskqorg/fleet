# tests

* `trial/*.test.ts`, `go/*.test.ts`: outside tests of the Go coordinator over HTTP, run by `tests/go/run.sh` (part of `pnpm test`). `harness.ts` starts the binary on a fresh Postgres database; `s3-fake.ts` is the fake store.
* `ui/*.test.ts`: unit tests for `packages/ui` and the app, run by `pnpm test`. `*.check.ts` and `*.check.mjs` are browser checks against the Go binary (`seed.ts` writes their fixtures).
* [`performance/`](performance/README.md): deterministic synthetic interface fixture/manifest, isolated coordinator/PostgreSQL and separate Chromium workload driver. Full capacity runs require reserved Linux/browser placement; ordinary CI runs only its small pure fixture assertions, not heavy load. Original-reference, alternate-profile, deployed/live and missing proof stay separate.
* `executor/*.test.ts`: MCP adapter tests (captured stdio replay, artifact path confinement) against the Go executor binary (`FLEET_EXECUTOR_BIN`, else `go build`). The executor's own tests are `go test ./executor` in `go/`.

CI (`.github/workflows/ci.yml`): the `go-tests` matrix (gated by job `go`) runs `go vet`, `go test -race ./...`, the executor MCP tests and `tests/go/run.sh` in four file shards against a `-race` coordinator; job `app` the UI unit tests; job `browser` the `*.check.ts` browser checks and the design report.

* `../scripts/test-rule-report.ts`: static requirement/risk inventory for test declarations (TypeScript and Go); warnings, except that with `--strict` (CI) a case in `go/` without both fails; `--self-check` checks the inventory logic.

* `ui/test-selection.test.ts`: deterministic shadow-selector fixtures (event identities, full group union, renames/deletions, unknown impact and exact-candidate evidence refusal), run with `node --test tests/ui/test-selection.test.ts`. No database/browser setup.

CI keeps the `test-selection` and `test-qualification` artifacts for 7 days (the release gate downloads the latter). The narrow qualified rollout may omit unrelated families only for prose and the inspected Lab-create boundary; the latter artifact binds the plan to actual executed or skipped results. Unknown paths/history and nonempty `FLEET_TEST_FULL` retain full execution. See [selected-gate qualification](../docs/designs/fleet-delivery-pipeline.md#selected-gate-qualification) before enabling any omissions. Warning reports run separately from required behavioral completion; release checks qualification rather than waiting for warning jobs.

* `go/project-resources.test.ts` runs the real PostgreSQL processor proof in `go/coordinator/resource_projection_test.go` on an isolated harness database, then checks opt-in service processing, restart/backlog retention and accepted in-run native usage. It also verifies that prepared public reads remain disabled by default. Its bounded distinct-source case uses the performance runner's actual canonical SQL and one-snapshot proof query: one included leaf publishes while another is deliberately held pending, then exact epoch/revision/calls/errors and replay/final independent sums are checked. This is protocol proof, not capacity acceptance. Pure contribution and legacy reasoning/API cases run with `cd go && go test ./coordinator -run '^TestResource(ContributionExact|LegacyReasoningAPI)$'`. These checks qualify the processor protocol; they do not establish browser latency or the load envelope.
* `go/project-resource-api.test.ts` uses an isolated processor-enabled PostgreSQL fixture for real operation authorization, progress, configuration isolation, epoch-bound C-order windows, surviving anchors, source-history locking, committed summary SSE/XID filtering and reconnect/revoke recovery. Its public HTTP large-native-key case admits and persists a near-1MiB escaped source report, then exercises compressed next/previous cursors, packed query200/deleted anchors, legacy cursor compatibility and bounded malformed/expansion inputs. Its targeted `TestResourceAPIBoundPaths` also covers the generic host binding seam. The full merge gate remains CI-only.

* `ui/api.test.ts` and `ui/store.test.ts` exercise injected access/baseline transitions, late universal-operation replies, retry fences, identity-scoped authored input, coalesced prepared scheduling and bigint versions. `ui/composer.test.ts` and `ui/virtual-list.test.ts` mount the real shared controls in Chromium with `FLEET_CONTROL_BROWSER=1` (run by the existing browser CI entry, skipped in the app-only unit job) for late-success/new-input and key/offset/deletion/empty recovery.
* `ui/access-gate.check.ts` runs against the built app and isolated PostgreSQL with both resource flags enabled, through an actor-selectable authenticated fixture proxy. It covers independent editable detail under delayed resources, dirty definition conflicts, configuration-only readback, real source-to-render updates, continuous windows and mounted revoke/identity races. `node tests/ui/access-gate.check.ts` is the focused entry; CI also calls it from `ui/conversations.check.ts`. `FLEET_BROWSER_SHOTS=<ignored directory>` captures actual browser screenshots for visual inspection. This small fixture does not establish the declared load envelope or production activation.
* `ui/project-editor.check.ts` holds an actual pre-save configuration response across a verified save and checks that the mounted editor retains the saved revision/hash. It also posts a real host readiness event, retains its result across an unchanged reload and invalidates it on a changed source. CI calls it from `ui/conversations.check.ts`; the focused entry is `node tests/ui/project-editor.check.ts` on an isolated PostgreSQL/Chromium runner (`FLEET_EDITOR_PREPARED=1` selects prepared reads).

* `go/interface-writer.test.ts` proves fixture-only eight-session FIFO pipelining, independent durable commit receipts, partial error prefixes, cancellation/backpressure and exact prepared parity on real PostgreSQL. `ui/interface-eventsource.test.ts` (the existing browser check entry) compares real native SSE before/after capture: credentials, reconnect/Last-Event-ID, custom events, duplicates, cancellation, navigation, untrusted dispatch and failed/full evidence sinks. These focused protocols are not capacity or live acceptance.
