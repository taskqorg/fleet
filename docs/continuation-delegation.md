## Coordinator delegation milestone

Implemented coordinator-only operation; runtime MCP/UI integration is pending. Existing profiles remain unchanged and delegation is denied by default. A trusted repository agent profile may optionally declare `delegationProfiles: ["baseline"]` (accepted IDs: baseline and design-rules, unique, at most two). The effective grant is retained inside the execution's existing agentConfig snapshot and digest. Configure this only in the intended scenario; this milestone does not enable a live grant. The Rust profile validator/native mapping must support the optional field before native qualification with it.

Executor sends POST `/api/hosts/receipts` with machine authentication and exactly `{hostId,commandId,executionId,delegation:{requestId,profileId,input}}`. The executor must obtain envelope identities from its trusted invocation context, never model arguments; the model supplies only delegation fields. Coordinator verifies assigned host, command/execution binding, started start command, effective profile grant and non-child/non-continuation caller. It derives parent session, new child session and result route itself. A host bearer is a trusted executor boundary, not protection against a compromised executor. Host credentials must never enter model context.

Typed delegation has no lifecycle status and does not complete its parent. The response is a durable delegation record with server-generated childExecutionId/childSessionId and resultRoute. Stable `(parent execution, requestId)` returns the same record, including after lifecycle completion; conflicting input/profile reuse returns 409. One child per invocation and no delegation from child or automatic continuation bound this milestone; explicit human follow-up is a new invocation. No roles or review stages are hardcoded.

Parent must finish its native turn and send the ordinary completed receipt after submitting work. Until that receipt, child start commands are withheld, including for unknown parent state. A failed/stopped parent does not release the child. This is turn yielding, not synchronous waiting. Native internal subagents do not participate.

On authenticated poll, a SQLite transaction reconciles retained child terminal results and creates at most one parent continuation. Child event records and artifact references are copied into the retained result; automatic follow-up consumes this actual observation, including failure state, with child content labelled untrusted. Result data is retained even when routing cannot proceed. No native session ID means result-retained pending supported continuation. Stop/failure suppresses new continuation; a parent stop also withholds an already queued automatic continuation. A command already delivered is subject to existing executor stop semantics; stopping the old parent does not prove that another native invocation has stopped.

Continuation reuses the parent's Fleet session ID (thus existing working directory) and nativeSessionId, resolves its current trusted profile and retains its new snapshot/digest. Prior snapshots and artifacts remain untouched. Unresolved executions in that session block automatic continuation. Unknown child state never creates a follow-up or duplicate launch. Repeated polling/restart uses the stored continuationExecutionId, never model inference, to deduplicate routing.

GET `/api/executions/:id/delegations` exposes linked records for parent, child or continuation under existing browser auth. GET session history also includes related delegation records. These are data APIs for the next UI layer, not a new machine route. All four machine POST routes are preserved.

Evidence: `npm test` passed all seven coordinator tests; `npm run build` passed. The focused delegation fake-executor test covers machine/browser separation, wrong host/command scope, dedup/conflict, sequential progression, unknown withholding, recursion refusal, durable actual event delivery across restart, native thread forwarding, repeated polling and parent-stop withholding. This is coordinator evidence only; no native, UI, deployment or public qualification is claimed.

## Current candidate: runtime and ordinary session UI

This section supersedes earlier pending-layer statements. Rust accepts optional delegationProfiles without changing profiles that omit it. Repository profile IDs use a bounded safe filename grammar rather than an accepted-role list. The two lab variants and their files remain unchanged. Packaging copies all trusted profiles plus the contract; website-review and website-reviewer are separate explicit profiles. Profile selection is browser-authorized POST `/api/sessions/:id/profile` with exactly `{profileId}` and refuses active executions. The ordinary UI button selects website-review; it does not start a run. Future message resolution still reads the current profile, retaining each execution snapshot.

Executor embeds delegation.py and launches it as fleet MCP only for an effective nonempty delegation grant. Its request_child schema contains only requestId/profileId/input. Executor-owned argv binds journal path, assigned host, command and execution identity. No bearer, native/browser credentials or coordinator URL is passed to the adapter or returned by the tool. Native's existing cleared environment remains in force. This is still a trusted same-user executor boundary, not an OS containment claim.

MCP writes a stable invocation/request record and the typed receipts envelope into the existing SQLite outbox in one transaction. Reusing the identity with changed arguments fails. Executor flush retains coordinator response before removing the outbox item; replay after a crash is coordinator-idempotent. Network/server failure retains the outbox. Coordinator 4xx rejection is recorded as an error response and removed from outbox to avoid poisoning later lifecycle delivery. MCP waits at most eight seconds for transport acknowledgement, never child completion. Acceptance returns the durable child reference and an instruction to finish the turn. Unacknowledged submission returns pending, not invented acceptance; retry uses the same requestId. The adapter currently exposes submission; actual child findings are received through the durable parent continuation and browser history APIs.

After the parent completed receipt, child dispatch binds actual retained HTML/CSS from the latest artifact-bearing parent-session execution no later than the parent. It transfers source text, path, execution and digest as explicit input, not another workspace's path. Missing source or source JSON above 128000 characters withholds dispatch with routingError. The child uses a separate working directory and configured read-only review instructions; it is not given the parent's writable directory. These are instructions plus workspace separation, not proof against a malicious same-user agent. Source and review text are untrusted input. One child per native invocation, no child recursion and no delegation from automatic continuation are explicitly scoped prototype limits, not universal Fleet rules.

Poll reconciliation and source binding use one durable transaction. The ordinary UI shows related execution links and observed parent/child/continuation states, actual reviewer assistant findings, and retained previous/new previews. Automatic continuation messages display a short result receipt instead of raw JSON. HTML/CSS differences below 131072 bytes per side show the changed line range with removed/added text, trimming identical prefix/suffix. This intentionally presents one replacement block, not a minimal multi-hunk patch; nontext/oversized content explicitly reports text comparison unavailable. Immutable artifacts remain separately accessible. Screenshots: evidence/continuation-desktop.png, continuation-mobile.png, continuation-preview.png and continuation-frame.png. Full-page screenshots may omit iframe painting outside the viewport; the individual frame screenshot was opened and shows the new rendered heading.
