## Version-matched cause

In [exec/src/lib.rs](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/exec/src/lib.rs), thread_resume_params_from_config (lines 1481-1506) sends model, cwd, approval, sandbox and config, but leaves developer_instructions at ThreadResumeParams::default(). Its thread_config_overrides_from_config (1509-1514) forwards only bypass_hook_trust, not developer_instructions from CLI -c. ConfigOverrides also initializes developer_instructions to None (612). Thus supplying a current CLI configuration is not evidence of updated developer context for a retained thread.

The installed binary's `codex app-server generate-json-schema --out /tmp/fleet-resume-protocol-0167` succeeds without a model call and emits v2/ThreadResumeParams.json with developerInstructions. Version-matched [protocol/v2/thread.rs](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs) declares developer_instructions at line 414. [thread_processor.rs](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/app-server/src/request_processors/thread_processor.rs) destructures it at 4005 and passes it into build_thread_config_overrides at 4216. This is a supported developer instruction channel, not user-message text. Its actual model-context delta remains a native qualification requirement.
