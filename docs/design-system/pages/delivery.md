# Delivery (operator)

App only. Every page renders [app-shell](../patterns/app-shell.md) with the [nav rail](../controls/nav-rail.md). The book's mockup (`#/delivery` in [mockups.html](mockups.html)) shows the same composition with fixture data.

**Purpose.** Answers, in this order: what in delivery needs a look, what is moving now, and what the pace is. Covers the pull requests of all connected projects, from open to installed on hosts.

**Layout.** [List and detail](../patterns/list-detail.md), like Tasks ([D: owner, 2026-11-15](../decisions.md)).

*Control column.* The page head shows the age of the last GitHub read (red after 15 minutes) and a `public GitHub` chip while no key is on the `github` connection. Under it, the shared [list view](../patterns/list-view.md) over the rows `delivery_status` holds (the page filters, groups and sorts them itself): search (`state:` and `project:` terms); the system presets **Needs me** (Checks failed, Queue failed), **In flight** (every stage but Installed and Merged) and **Installed** (Installed, Merged), which set the stages only, then the person's own views; the [state counters](../controls/state-counters.md) of the `delivery` family; Select, Group (Stage, Project, None) and Sort (in stage since, opened; oldest in its stage first by default). Grouped by stage in attention order: Checks failed, Queue failed, Queue checks, Waiting in queue, PR checks, Open, Releasing, Installing, Installed (collapsed when the page opens), Merged (repositories without releases). A row: stage icon, title and `#number`; on the right the repository (when not fleet), the release and the time in the stage, red past the stage's P90. Pins, selection and the row menu (Open on GitHub) work as in every list. A row opens the pull request in the work area.

*Work area, nothing open:*
1. **Needs a look**, only when something does: the open regressions (`delivery_regressions`), pull requests whose checks failed or that left the merge queue, and pull requests past their stage's P90, as [problem rows](../controls/problem-row.md); the latest 3 and `+K` (OR-30).
2. **Moving now:** one row per pull request not yet installed, in attention order: stage icon, `#number`, title, a [norm bar](../controls/norm-bar.md) of the time in its stage against the stage's P50 and P90 (red past P90), the time in stage, and the P90 in text.
3. **Pace** (the fleet repository's recorded history; hidden for a person focused away from fleet): a range choice (24 h as twelve local two-hour buckets, 7 days, 30 days from the first recorded day); [totals](../controls/number.md) of open-to-installed P50 and P90 against the 14-day baseline, pull requests merged (and per day), queue removals (and how many were flaky); then on one column grid of calendar days in the viewer's zone ([day chart](../controls/day-chart.md)): **Open to installed** (P50 bar with its P90, the P50 and P90 values under it, red above the baseline P90) and **Merged** (bars with their counts, the day axis); a day without install times is "not measured", a day where only some pull requests were measured through install is "partly measured" (half opacity, the count in its tooltip), today is "part of the day" (striped), the scale tops at about P95 and a figure above it shows its true value. **Where the time goes** is one [share bar](../controls/share-bar.md) for the range or the picked day: the mean per pull request of PR checks, Queue, Release and Install over those measured through install. A click on a day picks it in both charts and filters the list to the pull requests merged that day, shown as a removable chip; a second click clears it.

*Work area, a pull request open:* the title, stage, author and age; totals (open to installed or lead so far, queue runs, removals and flaky ones); the stages on one time axis, each a time strip with its duration (a stage without its own end ends where the next starts); the merge-queue runs with their conclusion and failed jobs; the hosts it is installed on. Other repositories, and fleet pull requests not merged yet, show what the current read knows.

| Inventory item | Shown by |
|---|---|
| Delivery stage of each change (review, merge, deployment) | The list, grouped by stage; the opened pull request's stages |
| Where delivery waits | Needs a look; red time in stage; the red norm bars |
| Delivery pace and regressions | Pace totals against the baseline; Open to installed per day; Where the time goes; regressions in Needs a look |

**Live.** Delivery reaches the page through the change stream: each pass that changes a project's pull requests writes `delivery-state:<project>`, and each history refresh writes `delivery-history`, both change kind `delivery`; the page re-reads on that change, and every 5 minutes as a fallback. With a key the coordinator reads GitHub every minute (pull requests, active and the latest finished workflow runs of pull requests and of the merge queue, releases); without one, the fleet repository every 6 minutes. Installed: every host seen in the last hour runs that release or newer.

**Data.** `delivery_status`, and for Pace, the norms and the opened pull request `delivery_history`, `delivery_baseline` (14 days) and `delivery_regressions` ([delivery health](../../designs/fleet-delivery-pipeline.md#delivery-health)). The view (stages, search, preset, group, sort, selection, range, picked bucket, opened pull request) is in the URL.

**Norms per stage** ([D: owner, 2026-11-17](../decisions.md)). Red means past the stage's P90 over the last 14 days, from `delivery_baseline`: PR checks (`pr_ci`), Waiting in queue and Queue checks (`queue`: both are time in the merge queue), Releasing (`release`), Installing (`install`); the P50 and P90 rows under Open to installed use `total`. Open has no norm (people work there); Checks failed and Queue failed always need a look. The norms are the fleet repository's history, so they apply to its pull requests only; other repositories' times are never red. Without a baseline no time is red.

**Unknown is not zero.** When some GitHub reads failed, the stage counters are unknown (`?`), an alert names the failure, and the rows are the last ones read, said so.

**Open.** Workers waiting to land is no longer shown; Fleet keeps no record of the waiting worker itself. On a narrow screen the work area shows only an opened pull request, so Pace is not reachable there yet.
