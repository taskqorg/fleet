# Owner rules

Read this first in every design or UI session. These rules are what the owner likes and wants to see, and they apply everywhere. They are instructions, not gates. `pnpm run check:design` warns where it can see a breach.

Source wording: [specq owner preferences P1–P16](https://github.com/taskqorg/specq/blob/main/design/owner-preferences.md). Decisions: [D6](decisions.md).

If an owner rule conflicts with common practice, the owner rule wins. Two exceptions always hold: touch targets are at least 44 px on touch devices, and contrast meets the WCAG minimums.

## Principles

Every screen serves these three, in this order. A rule below that conflicts with them is changed, not worked around.

1. **Glance.** Open Fleet and see at once who works, how much work is in flight and what is stuck. Detail is one click away, never in the way.
2. **Work through conversation.** Every job, operator or architect, is done by talking to a session: a bot or a project PM. Sessions are the home of the product; Home lists them, and the same session is reached from the web app and from Telegram.
3. **Details on demand.** Show what a person needs to understand and to talk. Ids, metrics, tool calls, cost and qualifiers fold away and open on click.

The principles, the rail and the new rules are drawn on the design board: [rules-v2.bl](board/rules-v2.bl).

A rule marked *Target* is approved and not built yet; until it is built, the current screens keep the behaviour the rule replaces.

## Rules

| Rule | What to do |
|---|---|
| **OR-1 Icon first** | If a registry icon shows the meaning, show the icon with a tooltip, not a word. Every icon has an accessible name. |
| **OR-2 Compact time** | Write times as `4m`, `2h`, `3d`, `12 Nov`, `12 Nov 2025`. The exact time is on hover, and the long form ("4 minutes ago") is the accessible name. Use the shared live age control from `packages/ui` for relative timestamps. |
| **OR-3 Navigation anchors** | Every section, menu item and workspace has one stable registry icon next to its name. |
| **OR-4 Everyday controls first** | Design lists, tables, filters and forms before pages. This is the order of work. |
| **OR-5 Apple baseline** | Apple HIG numbers fill any gap no owner rule covers. The owner rules make Fleet denser, because it is a tool for professionals. |
| **OR-6 Stable live updates** | Values update in place with fixed-width figures. A changed value tints briefly: green or red only where up or down has a known meaning, otherwise neutral. Inserted rows never move the row you are reading. |
| **OR-7 No added arrows** | Never add an arrow next to a value or in a pill to show direction. Example: the new-rows pill says `12 new`. |
| **OR-8 One icon set** | Icons come only from the registry, which holds the TaskQ Lucide set. No inline SVG, icon fonts or emoji. |
| **OR-9 Scale-proof collections** | Any collection longer than a screen uses `VirtualList` or a searchable scope control. Never use a plain long list or `<select>`. |
| **OR-10 System first** | Work in broad strokes: map the whole system before polishing one page. |
| **OR-11 Infinite scroll** | Collections load continuously with filters. Show a count ("84 of 1,240") and jump to start or end. No pagination unless a decision allows it. |
| **OR-12 Pin anywhere** | Every catalogue, list and menu lets the person pin items. Pinned items show first in that same place. There is no separate Favourites section, and the pin is an icon. |
| **OR-13 Book before pages** | Pages use only controls from the book. Menus are left-aligned with action icons, and a page is not a pile of text buttons. |
| **OR-14 Informational popups only** | Tooltips, previews, right-click menus and short context menus may float. Forms and working tools never float: they open in the work area (OR-27) or inline. |
| **OR-15 Return by icon** | A return action is an icon with a tooltip, and only where browser Back does not already serve. |
| **OR-16 Distinct floating surface** | Every floating layer has its own surface colour, border and shadow in both themes. |
| **OR-17 No repeated words** | A word appears once per region. Let position, headings and icons carry repeated meaning. |
| **OR-18 Visual salience** | A small chip changes colour when something needs a look. Example: `2h` turns red when a task has run too long. Hover gives details, following the same rules. |
| **OR-19 Never hide what matters** | What a person needs to understand the state and to act stays visible: the state, what runs, what is stuck, what waits for them. Technical detail (ids, metrics, tool calls, cost, qualifiers) folds and opens on click (principle 3, OR-54, OR-59). |
| **OR-20 Tooltip discipline** | Add a tooltip only where it gives the operator real value, and decide this per element. Clear notation such as `2h` needs none. A tooltip describes that one element. It appears after a delay, stays small, and never covers a field being typed in. At the edge, move the hint within the visible viewport at its standard width. When the viewport itself is narrower, wrap at the available width. Essential facts on touch are reachable without hover. No large combined tooltips. Use `data-tip` with the shared `TooltipLayer`. |
| **OR-21 Hierarchy by importance** | A row's main content (for a task, its title) gets the most space and weight; never squeeze it to two words beside equal-width columns. Service fields (id, state icon, agent, time, counters, actions) are compact and grouped in one zone on the right. |
| **OR-22 State first in every list** | In every list (tasks, results, hosts, executions, artifacts, variants and others) the leftmost column is the item's state icon; it marks both the row and its state. The item's ID sits directly after its name, as a pair. A task row also shows lifecycle facts that matter: the harness mark while it runs, and the delivery stage (PR open, checks, merging, merged) as a compact chip. Service fields stay in the right zone. |
| **OR-23 Nothing jumps** | An element that appears or disappears (a loading bar, a status line, a badge) never moves the content around it. Reserve its space and change only its look, or overlay it. Example: the list loading bar keeps its height and is transparent when idle. |
| **OR-24 Three columns** | Catalogue sections (Conversations, Projects, Lab, Library, System) have three columns: navigation (collapses to icons), the control column (the section's catalogue with search, filters and counters) and the work area (the opened item, or the section's page). Home and Live are full-width pages right of the navigation; an open session is the conversation with an optional context panel (OR-51). No bar spans the whole window: the product name and the "need you" count sit in the navigation, and the area right of it has one shell header (OR-43). *Target* for Home and Live; until then the Overview's catalogue is the Needs-you inbox, and Runners and Spend have no control column. |
| **OR-25 One scroll per column** | A column has at most one vertical scroller, and it is a plain browser scroller. A scroller never sits inside another one, and the page itself does not scroll. Only code and wide tables scroll sideways, inside their own frame. |
| **OR-26 The whole row opens** | A click anywhere on a list row opens the item. Controls inside the row (pin, checkbox, menu) act on their own. Never make the person aim at the title. |
| **OR-27 Open in the work area** | A task, conversation, result, host or any other opened item fills the work area; a session opened from Home fills the area right of the navigation. It is never a floating, sticky or overlaid panel, at any width. Narrow work areas follow the [device rules](principles.md#narrow-work-areas). |
| **OR-28 One format per value** | Each kind of value (code, time, duration, count, money, score, state, person, agent, path, hash) has one look everywhere, listed in [formats](formats.md). Mono is for codes and numbers, never for sentences. Each screen shows first what the owner comes to it for ([what each screen answers](formats.md#what-each-screen-answers)). |
| **OR-29 Sum first, no zeros** | A counter block starts with the bold total (`Σ 12`), then the breakdown. A zero chip is hidden, and a block whose values are all zero is hidden. A status quick-filter chip with 0 shows only its icon, never `0`. |
| **OR-30 Latest N, then +K** | A long feed shows its N latest items and a `+K` expander. A block never grows past the page; it never pushes the rest of the column out of view. |
| **OR-31 Search is an icon** | Search in lists is an icon; the field shows only while focused or not empty. The app-wide search is the search icon on the right of the shell header (OR-43), tooltip "Search ⌘K"; it opens the palette (OR-32). |
| **OR-32 One palette** | The app-wide search is a Spotlight palette on Cmd+K and the header's search icon. With the focus panel (OR-34) it is one of the two floating working tools, exceptions to OR-14. It jumps by entity code and finds tasks, questions, conversations, results, sections, projects, hosts, agents and pipelines; each kind is one provider, so new kinds plug in. Its query syntax (`agent:claude host:mac`) is the same as list search. A row shows the item's state icon, title, code, project and age. Results in the focus (OR-34) come first, the rest follow muted under "Outside focus"; ignored projects are left out; a project row adds or removes it from the focus. A kind with a list section ends with "All N in <Section>", which opens that list with the query. Empty, it shows the focus presets, recent items and the query terms. The query, results and highlighted row are kept while it is closed, per tab. |
| **OR-33 Saved views** | Every list uses one shared saved-views control: system presets (Tasks "Running" is every non-terminal state) and personal views. A system preset sets only the state filter; grouping and sort stay. Views are stored on the server per person, and agents read and write them through MCP. |
| **OR-34 Focus** | One global project multi-select applies across the whole app and changes in one or two clicks. It is the focus chip in the shell header (OR-43): it names the focused projects (two, then `+N`) and is filled with the accent while a focus is set, so it never reads as "All projects". Its panel floats under the chip and moves nothing (an exception to OR-14): the system preset "All projects" and saved presets, and a project search for long lists. A project is in focus, normal or ignored. An ignored project is hidden everywhere for that person, also with All projects (lists, counts, search), by a server-side exclusion, so work outside projects and in projects missing from the project list stays; it is not offered in the picker and is restored from the panel's folded "Ignored (n)" section; a view whose URL names a project still shows it. When items that need the person (Needs you) belong to projects outside the focus that are not ignored, the chip shows "N need you outside focus" in attention tone; a click opens the Overview without the focus. Ignore is full silence: an ignored project is never counted. With All projects, or at zero, nothing shows. Navigation counters split the same way: in focus bright, outside dim ([nav rail](controls/nav-rail.md)). Focus, presets and ignored projects are stored on the server per person; agents read and write them. |
| **OR-35 Group and sort are shared** | Group and Sort (field and direction) are shared list controls and part of a saved view. Group is a registry icon with a tooltip, not a word. Tasks sort by most recently changed first by default. |
| **OR-36 Filters live in the query** | There is no separate Filter button. Filters are typed in search with the query syntax (OR-32). |
| **OR-37 No hover buttons, facts in the space** | A list row has no buttons that appear on hover; hovering moves and covers nothing. Pin and other row actions are in the row menu (right click, long press, Menu key or Shift+F10). Checkboxes appear only in selection mode (the Select button, Shift-click, `x` or the row menu), as their own column left of the state icon; the action bar then replaces group and sort. Pinned rows are a Pinned group at the top, kept whatever the filter or search, and each shows a pin before its state icon; a click on it unpins. The row's right zone shows live row facts in short form: time since taken into work, number of executions, time in the current state, agent icon, host icon. Row facts are one shared pattern that other lists reuse. |
| **OR-38 Human codes, never UUIDs** | Entities show their human code (`T-FLT-42`, [D17](decisions.md#2026-11-10-d17-human-entity-codes)) everywhere. A UUID or hash is never shown; it is a tooltip with click-to-copy only. A project abbreviation can change at any time and old codes still resolve. Generated titles never contain a UUID. |
| **OR-39 Detail shows the story** | A detail page shows the statement, lifecycle, result and decision. Technical ids appear only where truly needed, as an icon with tooltip and click-to-copy. No large empty fields. |
| **OR-40 Needs you first** | A question to the person shows on the card of the session that asks (OR-53); Home lists Waiting for you first, oldest first. Repeated problems collapse into one item (OR-58). *Target*; until Home is built, Overview "Needs you" sorts by urgency, then recency, and shows the latest 3 plus `+K` (OR-30), and project and host rows follow OR-29. |
| **OR-41 Resizable columns** | The navigation and the control column resize by dragging their divider. Widths are stored on the server per person; a double-click on the divider resets the width. Every column that opens and closes beside the page (the navigation, the session's context panel, any later one) is one [side panel](controls/side-panel.md): its toggle at a fixed place in the shell header, a divider, and open or closed and the width stored on the server per person by panel key. No panel is built apart from it. |
| **OR-42 Collapse without a jump** | The navigation collapse toggle is the first item of the shell header (OR-43), right after the navigation. Collapsed and expanded navigation map 1:1: same icons, same heights, only labels change (OR-23). The navigation ends with the current user block (avatar and name, avatar only when collapsed); a click opens a context menu with Logout (Cloudflare Access logout). |
| **OR-43 One shell header** | One header spans the area right of the navigation, above the control column and the work area, whatever page is below. Left to right: the collapse toggle (OR-42) and the section title, the page's only top heading (a column has no heading of its own), then the section's own actions as icons (Conversations: New conversation); on the right the focus chip (OR-34) and the search icon (OR-31). A right-panel toggle goes after search once a right panel exists. At phone width it keeps icons only and never scrolls sideways. Its height contains the full hit targets for the active input mode. On Home and Live the header holds only the section title, the focus chip and the search icon. |
| **OR-44 Entity card** | Every reference to another object (a code such as `T-FLT-42`, `#643`, a release tag, or a kind icon for objects without a code) is one control, `EntityCode`. A click, tap, Enter or Space opens its card: kind and code, state, bold title, project, agent and compact time, a few facts, then Open first and the copy actions; it never navigates by itself and never opens on hover. Escape, a click outside or the code again close it. It is an informational floating layer (OR-14, OR-16), one at a time, and moves nothing (OR-23). A human code has a copy icon in a reserved slot, shown on hover, focus or touch. See [entity card](controls/entity-card.md). |
| **OR-45 Diff from default** | Configuration and comparison views (agents, projects, pipelines, Lab variants) show identity plus **only** fields that differ from their base default (harness default, `variantOf` base profile, shared project defaults, or Lab baseline). Unchanged inherited defaults stay collapsed in a single expandable `Inherited defaults (N)` row so differences stand out at a glance. No `override`, `overridden`, or `custom` badges or words, and no `t-attention` tone on normal configuration values; show the base default only in a tooltip if useful (OR-20). |
| **OR-46 One nav level, no second shell bar** | One global navigation level (`NavRail`) and one `ShellHeader`. The rail has seven sections: Home, Live, Conversations, Projects, Lab, Library, System ([information architecture](../designs/fleet-ia-and-journeys.md#1-closed-8-section-information-architecture)). Horizontal `<nav class="sub-nav">` above columns is forbidden. Section object navigation lives in the Control Column. `TabBar` is allowed **only** inside the Work Area for facets of a single opened entity (for example a project's `Sessions · Tasks · Delivery · Results`). |
| **OR-47 One-way causality & URL truth** | Strict left-to-right flow: `NavRail` → Control Column → Work Area. Work Area tabs never rebuild the Control Column. Every opened item (including Lab use cases, entity creation, `Limits`) has a URL and renders in the `detail` slot with an icon `Close` button in `.detail-h` (OR-15). `ListDetail` stays mounted while loading (skeleton inside the column, never an early return replacing `ListDetail`). |
| **OR-48 Two catalogue engines only** | The Control Column uses strictly `ListPagePanel`, `CatalogueTree`, or none (`Spend`, `Runners`). Raw `<div class="vl-wrap">` catalogues in the Control Column are forbidden. Section actions (`New …`) sit in `<ShellActions>` (OR-43), not in a Control Column `<header class="page-h">`. |
| **OR-49 One control per job** | `TabBar` (`packages/ui`) is the only tab control (no raw `role="tablist"`). `Choice` is only for 2–5 fixed options, never for project or entity lists (OR-9) and never as a single-option checkbox. `EntityCode` (OR-44) is used for every entity link. |
| **OR-50 Home is sessions** | *Target.* The first screen is Home: active sessions as cards (what each does now in one line, its question with answer buttons), then asleep bots with Wake, a composer that picks who to talk to (project PMs, bots, a new session from a preset), and one pulse line (working, queued, done today, blockers). Order: Waiting for you, Failed, Working, Queued, Asleep; a finished session leaves Home and stays in Conversations. A quiet Home says what happened while the person was away. |
| **OR-51 One session view** | *Target.* Every bot, PM and task run opens in the same conversation view, from Home, Conversations, Projects or a link. Beside it, a collapsible context panel shows the session's plan with done items checked, its timers (pause, edit, cancel), automations and swarm members; on a phone the panel is a sheet. |
| **OR-52 Tools fold into one line** | *Target.* Consecutive tool calls and system events in a conversation become one quiet line that says what was done and how long it took, expanded on click. Repeated attachments, heartbeats and internal notices are never shown. |
| **OR-53 Questions are actions** | *Target.* A question from an agent is a card with its choices as buttons and a free-text answer. The answer edits the card in place. The same question shows on the session's card on Home and in Telegram. |
| **OR-54 Quiet by default** | *Target.* A conversation and a session card show no metrics header, no model badge per message and no cost. Model, tokens, cost, CPU, memory and ids are under Details. Lists show cost only where cost is the question (Spend). |
| **OR-55 One state vocabulary** | *Target.* Sessions, bots, tasks and runs use one set of states with one word, icon and colour each: Working, Waiting for you, Queued, Done, Failed, Stopped, Asleep. Synonyms such as Succeeded, Completed, Cancelled leave the interface. |
| **OR-56 Red means trouble** | Red is only for failures, dead hosts and blocked work, so the eye finds trouble first. Waiting for a person is attention (amber); running is the running tone. |
| **OR-57 Every screen has one home** | Every screen belongs to one rail section, which stays highlighted while the screen is open. There are no orphan routes. *Target:* a URL is section, kind and human code (OR-38), never a UUID. |
| **OR-58 Repeats aggregate** | *Target.* Identical events or problems collapse into one item with `×N`, the cause and the newest time, never one row each. |
| **OR-59 Qualifiers in details** | *Target.* Marks such as `≈`, `≥`, "partial" and the subscription mark move to the tooltip and Details; the main view shows the rounded value. |
| **OR-60 Phone first-class** | At phone width the rail becomes a bottom bar of five: Home, Live, Conversations, Projects and More. *Target:* a row title keeps at least 60% of the row width; service fields wrap below it or fold. |
| **OR-61 Risky actions confirm** | *Target.* A radical action (release to production, delete or ban accounts, message real users, change keys or money, drop data) starts only from a confirmation card that names its exact scope and the way back. The card is a question (OR-53), so it shows on Home, in the session and in Telegram, and only a person allowed to approve that scope can confirm it. |
| **OR-62 Brilliant first** | Every visible change to the interface (a screen, a block, a row, a state, a layout) is drawn on the design board in Brilliant first and approved by the owner there, before code is written. The pull request that builds it links the approved canvas and commits it ([board](README.md#design-board)). A fix that restores what a canvas already shows needs no new drawing. |
| **OR-63 Work facts** | Every list row of work (a task, a run, a pull request, a repeated event) shows the shared [work facts](controls/work-facts.md) in its right zone: `×N` attempts from two, agent mark, then the time (OR-64); the latest attempt and the time in its state are in the tooltip of the time in work and in the detail. A row an order of magnitude above its peers' median in attempts or time in work takes the attention tone; no fixed limit decides. |
| **OR-64 Time last** | In every row and card the time is the rightmost fact: a waiting time, a time in work, a latest attempt, an age or a duration comes after every other fact and chip, so the times line up in one column down a list and are read at a glance. A row's other facts, its stage and its agent mark come before it ([work facts](controls/work-facts.md)). |
