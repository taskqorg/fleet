# Spotlight palette

**Code.** `Spotlight`, `sectionProvider`, `spotlightMemory`, `FocusPresets` and the `SpotlightProvider` and `SpotlightItem` types in `packages/ui`; the app's providers in `app/src/main.tsx`; the server operation `search` (`go/coordinator/search.go`, `contracts/ops-people.schema.json`).

**Purpose.** Find and open anything from anywhere ([OR-32](../owner-rules.md)). With the focus panel it is one of the two floating working tools, exceptions to OR-14.

**Anatomy.** A floating panel near the top of the window (OR-16 surface): a search field, then results grouped by kind: Sections, Tasks, Questions, Conversations, Results, Projects, Hosts, Agents, Pipelines.

* A result row is the item's registry state icon (task, question, session and artifact states: running, needs you, failed, done and so on), or the kind icon where the kind has no such state (sections, projects, hosts, agents, pipelines; a definition's git sync state is not a registry state). Then the title on one line with an ellipsis, the entity code ([D17](../decisions.md#2026-11-10-d17-human-entity-codes)), the project, and the compact age of the last change (`Ago`, OR-2). The project is left out while the focus is exactly one project and the row is in it (OR-17). The project keeps its width up to 8rem (6rem at phone width), then ends with an ellipsis; a long title truncates instead, so the project never shrinks to a letter.
* A conversation found by words of its first message that its title does not show (the first message is often a long instruction) adds one muted line under the title: up to 80 characters of that message from the word just before the first match, with an ellipsis where it is cut (`snippet` of the hit; a word whose first match lies in the first 24 characters, which the title shows even at phone width, adds none). A recent item has no snippet, which belongs to its query.
* Results in the person's project focus ([OR-34](../owner-rules.md)) come first. Results outside it follow under one "Outside focus" heading, again grouped by kind, in muted text. Hosts, agents and pipelines have no project and are never outside. The server marks each hit outside the focus (`outside`), so the order and the split follow one rule.
* A project row has a focus button: it adds the project to the focus or removes it (pressed while in it). Alt+Enter does the same on the highlighted row. The palette stays open and asks again, so the results reorder at once.
* A kind whose section list takes the query (Tasks, Conversations, Results) ends with an "All N in <Section>" row with an arrow icon when its list holds more than the focused rows shown. It opens that list with the same query as its search (OR-36). N is the count the server gives for the query in the focus, which is what that list shows. Projects, hosts, agents and pipelines have no such row: their sections filter in the browser and take no query in their URL.
* With an empty query: the focus presets ("All projects" and the saved ones) as one-click chips, the recently opened items (up to 6, this tab only) as results, with their kind icon and without a state or age, which would be stale, and the query terms (`agent:` `host:` `state:` `project:`); a click on a term adds it to the query.

**Providers.** Each kind of thing found is one provider: `{ id, label, find(query, signal) }`. Sections are found in the browser from the navigation items. Every other kind comes from one `search` call, which agents call as the MCP tool of the same name (fleet.md R2, R7). A new kind is one more provider in `searchProviders` on the server, or in the app's list when it needs no server. The app sends the focus as `projectIds`; the server puts each kind's hits in the focus first, so a limit of 8 per kind never hides a focused hit behind outside ones, and returns `counts` for the "All N" rows.

**Query.** Free text plus `field:value` terms: `agent`, `host`, `state`, `project` (`agent:claude host:mac flaky`). This is the list search syntax (OR-36): `searchWhere` in `go/coordinator/search.go` applies it to `task_page`, `sessions_list` and `artifact_list`, and `matchSearch` in `packages/ui/src/search.ts` to lists filtered in the browser. A term for a field a kind lacks matches nothing, so `agent:claude` finds tasks, conversations and agents only (`agent:` is the harness of the latest execution of a task or conversation, finished work too, and an agent's configured harness). Pipelines take no term. Every D17 code in the query (`T-FLT-42`, `Q-FLT-3`, `C-FLT-7`) is resolved first, old codes of a renamed project too, and shows the current code; a code jump is never outside the focus. Then, inside each kind, the focus first, then tasks whose id or code starts with the text, then recently changed. Conversations are found by their first message, code or id, archived ones left out as in their list (a match deep in the message comes with its snippet); results by name.

**Ignored projects.** A person's ignored projects ([OR-34](../owner-rules.md)) are left out of every kind with a project (tasks, questions, conversations, results, projects) and of the "All N" counts, so they are never among the results outside the focus either. A query that names the project exactly (`project:<its id>`) or a code jump finds them anyway. The empty palette's presets leave ignored projects out, and a preset of only ignored projects is not offered. An agent's search is not filtered this way.

The Results list's own `media:` and `since:` terms are applied in that list only; the palette reads them as words. Agents and pipelines are found by id or name, only by people with the architect role (their definitions are the architect's to read).

**Questions.** In the focus and outside it, open questions come first; answered and withdrawn ones follow with their state icon, so an old decision is still found by its words. A question opens its task, or its conversation when it has no task.

**Kept while closed.** Closing the palette, by Escape, a click outside or opening an item, keeps the query, its results and the highlighted row. They are kept in memory per tab and per access generation, across navigation but not across a reload. On open the field has focus with its text selected: typing replaces the query, and the arrows browse the kept results, which are asked again in the background and keep the highlighted row (the first row when it is gone).

**Behaviour.** Cmd+K (Ctrl+K elsewhere) or the search icon in the shell header (OR-43) opens it; Cmd+K again closes it. Results follow typing after 150 ms. Up and Down move, Enter opens the item in the work area (OR-27) and closes the palette; pressed before every provider has answered the typed text (a key typed just before it included), it opens that text's first result once they have, and typing on cancels it. Alt+Enter runs the highlighted row's action; on a row without one it opens the row like Enter. Escape or a click outside closes it and returns focus. When a kind fails, its rows go and a status says so; the other kinds stay. Tab stays in the field, and the field keeps focus while the palette is open: a page that focuses its own element behind it gives focus back.

**Accessibility.** `role="dialog"` named "Search"; the field is a `combobox` controlling a `listbox` of `option`s with `aria-activedescendant`. A state icon has the state's name; the age has its long form; the focus button has its action as its name and `aria-pressed`, and its option names Alt+Enter and the action (`aria-keyshortcuts`, `aria-description`), since the button inside an option is not reached on its own. The focus presets are a group named "Focus presets".
