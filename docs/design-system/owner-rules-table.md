# Owner rules: decision table

Decision 2 of the [methodology brief](methodology-brief.md). The owner decides per row: accept, change or reject the proposed OR wording, the check and the precedence. Source wording: [specq owner preferences](https://github.com/taskqorg/specq/blob/main/design/owner-preferences.md) (P1–P16, verbatim there; short paraphrase here).

Check types: **test** fails `npm test`; **lint** fails the design gate on code or rendered HTML; **review item** blocks page approval and is listed in the approval record.

Also from the brainstorm (not yet P-numbered, proposed as OR-17 to OR-19 after this table): minimal but sufficient with no repeated words; visual salience (a small chip like `2h` turns red when it needs a look); never hide important information that can be shown.

| P | Original (short) | Proposed rule | Check | Conflict with common practice | Proposed precedence |
|---|---|---|---|---|---|
| P1 | Show with an icon and tooltip what can be shown as an icon, not a word. | OR-1 Icon first. A state, kind or action with a registry icon is shown as that icon with a tooltip, not as a word. Words stay where no icon is unambiguous. | Lint: rendered labels that equal a registry entry having an icon fail unless rendered through <Icon>. Review item: new words that could be icons. | WCAG 1.1.1 / 2.5.3 and HIG: icon-only needs an accessible name; unfamiliar icons hurt recognition. | Owner rule wins. Every icon carries aria-label and tooltip (on hover, focus and long-press); first-time meanings come from the registry only. |
| P2 | Short, convenient time, 'ago' and date forms; very important. | OR-2 Compact time. All times use the registry formats: 4m, 2h, 3d, 12 Nov, 12 Nov 2025; exact time and zone on hover. | Test: formatter fixtures for every boundary. Lint: Date/Intl/toLocale* outside the formatter module fails. | Screen readers read '4m' as 'four m'. | Owner rule wins. Accessible name carries the long form ('4 minutes ago'). |
| P3 | Unicode icons on sections and menus as visual anchors. | OR-3 Navigation anchors. Every section, menu item and workspace has one stable registry icon next to its name. | Test: every nav item and section header in the book and routes has an icon id from the registry; one icon per destination, no reuse for another destination. | HIG sidebars agree. P8 replaces Unicode with the TaskQ icon set. | No conflict. P8 decides the glyph source. |
| P4 | Lists, tables, filters, forms are the most important elements; maximum UX. | OR-4 Everyday controls first. List, table, filter and form controls are designed, specified and tested before any page. | Gate: plan.md orders controls before pages; a page work unit cannot start until its controls are approved. Behaviour tests per control (keyboard, scroll, empty, error). | None. | Process rule. |
| P5 | Apple as a trusted reference, but for professionals, not casual users. | OR-5 Baseline. Apple HIG numbers (targets, spacing, motion, scroll behaviour) are the base layer; owner rules override, and every override is listed in owner-rules.md. | Review item: each control spec names the HIG item it follows or overrides. Test: overrides list is non-empty only with a linked OR. | HIG favours roomier layouts than a dense pro tool. | Owner rule wins (density for professionals); HIG fills gaps no owner rule covers. |
| P6 | Fast, stable live pages: numbers don't jump; a changed number tints briefly (exchange style); native fast scroll, no jumps on insert. | OR-6 Stable live updates. Values update in place with tabular figures and fixed width; a changed value tints for about 2 s (green up / red down only where the metric's meaning is known, else neutral). Row inserts never move the first visible row. | Playwright: insert rows above and below viewport, assert layout shift 0 and anchor row offset unchanged; change a value, assert width unchanged and tint class present then removed; reduced-motion removes the tint animation, not the change marker. | WCAG 2.3.3 / reduced motion; colour-only change signal (1.4.1). | Owner rule wins; under reduced motion the tint is static for the same time. Colour is supplemented by the value itself, no arrow (P7). |
| P7 | No added direction arrow: extra symbol and content shift. | OR-7 No added arrows. No arrow glyph is added beside a value or in pills to show direction or position. | Lint: arrow glyphs (↑↓→←▲▼ and icon ids arrow-*) next to numbers or in pills fail. Fails the current '12 new ↑' pill. | Colour-only direction (WCAG 1.4.1). | Owner rule wins. Direction is conveyed by tint plus the accessible name ('up 3%'). |
| P8 | Use the TaskQ icons; one system. | OR-8 One icon set. Icons come only from the registry, which imports the TaskQ icon catalogue. | Lint: inline <svg>, icon fonts or emoji outside the registry fail. Test: every registry icon resolves to a TaskQ asset. | None. | No conflict. |
| P9 | No plain project list; controls must handle thousands to trillions of items. | OR-9 Scale-proof selection. Any collection that can exceed one screen uses a searchable scope control or a virtual list; never a full plain list or select. | Test: each collection control runs with a 100k-item fixture; DOM row count stays bounded and input stays responsive. Lint: <select> with more than a set of fixed options fails. | None. | No conflict. |
| P10 | Work in broad strokes; design the whole development system, not small screens. | OR-10 System first. Design starts from the whole system map (all workspaces and their objects) before refining one page. | Review item: plan.md has a system map work unit approved before page units. Not automatable. | None. | Process rule; review only. |
| P11 | Pagination only if unavoidable; infinite scroll with filters everywhere. | OR-11 Infinite scroll. Collections load continuously with filters; visible pagination needs a recorded exception decision. | Lint: page-number controls fail unless the route cites an exception decision. Playwright: scroll to end loads more without moving content. | Infinite scroll hides the footer and position (WCAG 2.4); hard to reach the end. | Owner rule wins. Count ('84 of 1,240') and jump to start/end keep orientation. |
| P12 | Pin or favourite items in any catalogue, list or menu, as workplace personalisation. | OR-12 Pin anywhere. Every catalogue, list and navigation menu lets the person pin items; pinned items show first in that same place. No separate Favourites section. | Test: each list control exposes pin and persists it per person; book shows pin in every list control. | None. | No conflict. P13 limits repeated 'pin' words: the pin is an icon (OR-1). |
| P13 | Design book first; controls and approach collected there, then pages; no repeated words, no centred menus, no button clutter. | OR-13 Book before pages; no repeated words. Pages use only book controls. A visible word repeats at most once per view region; menus are left-aligned with action icons; actions are icons where OR-1 allows. | Gate: lint bans styling outside packages/ui. Test: repeated-word check per region on rendered routes; menu alignment test. | None. | No conflict. |
| P14 | No pop-up windows unless purely informative; working tools never in popups. | OR-14 Informational popups only. Tooltips and read-only previews may float; anything with inputs or actions opens inline (in place, a side panel within the layout, or its own route). | Test: no interactive element (button, input, link, select) inside any floating layer (role=tooltip, popover, dialog). Fails the current '+ Filter' popover and saved-filter menu. | Common practice uses menus, popovers and dialogs for filters and confirmations; WCAG allows them. | Owner rule wins. Filters expand inline in the filter bar; confirmations happen in place. Open: are context menus (right-click actions) allowed? |
| P15 | Back as an arrow icon, if needed at all. | OR-15 Return by icon. A return action is an icon with a tooltip, and only where browser Back does not already serve. | Lint: text links 'Back to …' fail. Review item: return actions are justified. | Conflicts with OR-7 only in glyph: a back arrow is navigation, not direction of a value. | Owner rule wins; OR-7 does not apply to navigation icons. |
| P16 | Dropdown menu with no background looked wrong. | OR-16 Distinct floating surface. Any floating layer has its own surface token, border and elevation in both themes. | Test: computed background of floating layers differs from page background and has a border or shadow token. | None. | No conflict; applies only to informational floating layers (OR-14). |
