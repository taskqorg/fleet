# Connected project prototype

One repository-defined Hello World project supplies rules/reference data and a web-research recommendation. An explicit method wins; otherwise project recommendation overrides shared default. One text-defined web_search step is the initial runnable pipeline subset. HTTP, MCP and web views call the same core operations and durable records. Direct sessions remain valid.

Record selected project/method, definition/context snapshots, step inputs/results, actual duration and reported usage. Persist dispatch intent before external effects; restore interrupted running work as unknown without replay. Quota/unavailable errors retain cause and never substitute method/account. Connections come from Fleet's API key list through fleet-gateway ([connections](designs/fleet-connections.md)); no credentials or connection paths enter project/profile/model data.

Authorized delivery extension uses a dedicated test repository/destination: project context → catalogue/search pipeline → tracked agent execution → verification/source integration → tracked deploy operation → observed publication, then a second version with retained prior outputs. Completion, integration and publication are separate facts. Local deterministic checks precede real calls/rollout; no unknown operation is replayed.

The approved coverage extends this subset to two repository-defined projects, direct search versus the one-step pipeline, durable operator questions, and an explicit stored project recommendation. A delivery retains its research run, agent execution and separate program-worker executions for source integration and publication. Program workers accept only host-configured project destinations; model output cannot choose a repository, command or deployment root. Unknown dispatches require reconciliation, never automatic replay. Existing direct sessions and native history remain unchanged. Mac and PDS18 proof, controlled failures and comparison evidence are recorded separately from local fixtures.

The Go publication route is the bounded `publication` pipeline step described in [pipeline format version 2](designs/fleet-lab.md#pipeline-format-version-2). Agents launch `publish-static` through `pipeline_run_create` with a stable request identity and an `index.html` example input, then read `pipeline_get`; a generating pipeline can select earlier step artifacts instead. The actual program runs in the coordinator service under its existing private destination ownership, and records that service separately from the configured `publication` authority. Compatibility program-host rows do not acquire a healthy heartbeat from a coordinator execution. Source storage, protected-URL byte verification, publication success and task acceptance remain separate facts. Existing host-only destination bindings are reused; no retired Python process or generic command daemon is restored.

Managed accounts are persistent metadata separate from agent profiles and host-protected bindings. Operators create/enable/disable records; only an authenticated eligible host reports observed binding readiness. Existing aliases remain migration inputs and compatibility references. A disabled managed account refuses new enqueue, including delegated work, without changing historical executions. Claude placement is Mac/Windows only. Native login and behavior-source qualification remain separate observations; a UI click cannot assert readiness. The prototype uses the existing machine authentication boundary; distinct per-host machine credentials remain a gap.

After the operator answers and starts a delivery, Fleet advances generation → source integration → publication through terminal receipts. The caller does not coordinate normal internal steps. A controlled publication-refusal operation is a separate acceptance probe and leaves an existing successful publication intact. The protected Fleet test-site destination uses the existing authenticated public web boundary; anonymous access is not implied.

Claude's explicit native-current credential binding may use the host HOME for the existing macOS login keychain while keeping a dedicated CLAUDE_CONFIG_DIR. Fleet supplies explicit system instructions, no setting sources, strict invocation MCP and disabled slash commands. Installed help distinguishes safe-mode (all customizations disabled) from bare mode (OAuth/keychain unavailable); neither is silently substituted for a working subscription/tool mapping. Full personal instruction/settings discovery exclusion needs native evidence before readiness is claimed.

An explicitly selected completed research result may supply a later delivery for the same project and method. Retain its original query/sources/usage; do not pretend it was another provider call. The laboratory can persist a comparison of two existing terminal executions without creating new executions. Native artifact paths are retained relative to output; the delivery boundary accepts the executor's canonical index.html/CSS names and historical output/ prefixes, rejecting collisions.

A catalogue method may nominate the default delivery agent profile; explicit profile selection wins. The guided Hello World method shares the exact existing search definition and chooses the design-rules instruction/tool profile. Explicit retained-source reuse requires the same project and search definition hash, and keeps the original research method visible. This permits a bounded comparison with fixed sources and changed agent instructions/tools. Managed aliases cannot bypass their account's disabled state; a trusted host default binding applies admission checks while historical native resume retains its compatible transport mapping.

Claude login readiness requires OS user metadata as well as the host HOME and dedicated CLAUDE_CONFIG_DIR in this installed build. Supply USER/LOGNAME from the executor's OS identity, never browser/model input. Fresh local status with that exact environment succeeds; omitting those fields returned logged-out even with an available default keychain. This is a launch environment defect, not evidence that the owner's persisted login was absent.

An explicit prior delivery may provide bounded immutable HTML/CSS as the base for a follow-up. Retain artifact IDs/digests and supply their source text as untrusted task data. The follow-up receives a fresh native execution in this slice; no cross-account native resume or automatic behavior inheritance is implied. Saved results and prior published releases remain inspectable.

Keep receipt duration separate from the available same-host thread-open→turn-completed observation window. Transport reconciliation can delay terminal receipt long after native completion; this delay must not be presented as model latency. Both intervals are observations, not a causal quality/performance score.

Native project MCP uses the same durable pipeline records. A slow search is acknowledged with its stored run identity; pipeline_get reads the eventual result without another provider call. Effect requests require stable IDs; read calls use fresh transport identities so polling cannot return a cached running response forever. Web callers may await the same core operation. The host route never holds the executor's exchange loop open for the entire provider request. Interrupted or unconfirmed work remains unknown without replay.
