## Current recovery slice contract

The demonstrated incident was an invalid duplicate transport sequence on a retained process.closed frame; the original native effect had already ended. Automatic outbox retry exists, but cannot pass a deterministic409. Add an inspectable append-only sequence authorization, not a native retry or journal SQL editor. Approval is restricted to process.closed conflicting with an existing resource observation, distinct event identity, exact original frame digest and authenticated owning host/execution. A later unchanged host resend receives a new reserved sequence; the native payload and original received identity remain retained. Other conflicts refuse repair. Neither approval nor event ingestion changes execution outcome; ordinary validated receipts remain authority. Agent tools require the same operator credential/Origin policy; no new native grant is added automatically.

Acceptance: focused API/MCP auth/ownership/conflict/idempotency checks, an isolated real executor fixture with one injected closure collision and no second native launch, program-worker crash/unknown preservation, browser approval/reload, and concurrent independent sessions with account/context/event/result separation. No paid/provider calls, live crash, auth change or credential copy.

Prototype boundary: the closure/resource sequence authorization is a source-specific prototype workaround, not a canonical architectural requirement or general recovery engine.
