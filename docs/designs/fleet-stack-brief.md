## Overview

Концепция: Go для координатора, исполнителя и вспомогательных скриптов; TypeScript с Preact и esbuild только для браузера; типы по цепочке `schema.sql` -> sqlc -> Go -> TypeScript; Python и Rust убрать; тесты только снаружи, по одному на требование спецификации; решение после пробного переноса с замерами.

Общий вывод семи проверяющих:

1. Концепция склеивает четыре отдельных решения: язык, доставка готовых файлов на хосты, источник типов, принцип тестов. Три из них не зависят от языка и делаются на текущем стеке за дни. От пробного переноса зависит только язык, и он снимает меньше всего перечисленных в handoff проблем.
2. Цепочка `schema.sql` -> sqlc -> Go -> TypeScript не описывает те места, где были ошибки расхождения. Это главный дефект концепции.
3. Тестовое правило не на что опереть: пронумерованных требований в репозитории почти нет.
4. Доводы за Go слабее, чем выглядят: исполнитель работает только на Unix, целей сборки две, а SQLite и вызовы ядра macOS ставят под вопрос сборку Go для Mac с одной Linux-машины без cgo.
5. В сравнении нет самого дешёвого варианта: оставить TypeScript и Rust, добавить генерируемые контракты, сборку исполнителя в CI и перенос Python в подкоманды исполнителя. Go должен выиграть у этого варианта, а не у сегодняшнего состояния.

## Analysis

### Блокеры

**Б1. `schema.sql` не может быть единым источником типов.** (все семь проверяющих)

- `packages/coordinator/db/schema.sql:6-13` — таблица `document(kind, id, data jsonb)` хранит сессии, события, сообщения, команды и наблюдения хостов как JSON без типов. Типизированные таблицы тоже несут `data jsonb` (строки 60, 98, 144); строка 32 называет это «формой записи, которую возвращает API». Всего около 30 колонок `jsonb`.
- Протокол исполнителя (`/api/hosts/poll`, `/events`, `/receipts`; `crates/executor/src/main.rs:181,951,1090`) не имеет таблицы вообще. В `contracts/prototype.json` лежат примеры, не схема (`contracts/README.md:6`), и этот файл никто не читает — ни код, ни тесты, ни CI.
- Обе ошибки из handoff (строки 45-47): `ev.item` против `ev.data` и правила outbox — сидят в содержимом событий, не в строках таблиц. Приложение читает `ev.data ?? {}` и дальше `d.item` без типов (`app/src/transcript.ts:14`).
- Следствие: sqlc выдаст для этих полей сырые байты. Проверка расхождения в CI будет зелёной, а расхождение останется.
- Дополнительно: шаг Go -> TypeScript не входит в sqlc, нужен второй генератор. А связка «таблица = контракт API» тянет каждое изменение колонки в браузер.

**Б2. sqlc плохо подходит к этому файлу схемы и этому хранилищу.** (`egm-design`)

- `schema.sql` — журнал миграций со своим разделителем (`packages/coordinator/store.ts:120-125`), с триггерами plpgsql, функциями `SECURITY DEFINER`, сменой типа колонки (строка 237) и `ALTER TYPE ... ADD VALUE` (строка 416).
- Запросы строятся на лету: `store.ts:101-106` (фильтр в SQL), 144 (условный курсор), `data->>'${k}'`. sqlc нужны статические запросы.
- Примет ли разбор sqlc этот файл — не проверено.

**Б3. Тесты «из спецификаций» не из чего писать.** (`egm-codebase-details`, `egm-comprehension`, `egm-implementation-readiness`, `egm-structural`, `egm-zoom-out`)

- Каталога спецификаций нет. Идентификаторы есть только у принципов R1–R6 (`fleet.md:7-12`) и сценариев UC1–UC10 (`docs/use-cases.md`); системные требования (`fleet.md:194`) — проза.
- `docs/spec-coverage-review.md:7`: спецификация «is not yet an implementation-ready contract».
- Тесты сегодня на требования не ссылаются (`tests/coordinator/tasks.test.ts:34`, `artifacts.test.ts:95` — только слово в прозе).
- Следствие: «один тест на требование», проверка равенства поведения и правило «тест без ссылки роняет CI» невыполнимы до отдельной работы по нумерации требований.

**Б4. Вывод записан раньше собственного условия.** (`egm-structural`, `egm-comprehension`)

- Текст начинается с «Fleet moves to two languages» и кончается «the decision is taken only after a trial». Handoff, строка 62: «Without numbers, no switch».
- «Python and Rust are removed» противоречит тому, что Rust-everywhere ещё участвует в сравнении.
- Не названо, кто решает и по какому порогу. Главная цель владельца — скорость работы агентов — в списке замеров отсутствует.

**Б5. Координатор работает на Postgres, не на SQLite, и тесты зависят от PGlite.** (`egm-implementation-readiness`, `egm-design`, `egm-codebase-details`)

- `store.ts:25,136` (LISTEN), `:70` (`pg_advisory_xact_lock`), `:139` (`pg_snapshot_xmin`), политики RLS (`schema.sql:174-191`), ClickHouse. SQLite в координаторе остался только в `migrate-sqlite.ts`.
- Тесты идут на встроенном PGlite (`store.ts:30`, `tests/README.md:3`). Это сборка под Node; аналога для Go проверяющие не знают (не проверено).
- Следствие: тестам на Go или Rust нужен настоящий Postgres на каждое рабочее дерево. Это меняет время тестов и стоимость параллельных деревьев в любую сторону; без этого замера пробный перенос измерит не то.

### Существенное

**С1. Трудная часть координатора — транзакции.** `store.ts:49-87` держится на `AsyncLocalStorage`: неявная транзакция, отложенные savepoint, учёт обречённых транзакций, очереди по области плюс advisory locks, повтор при 40001/40P01. В Go неявного контекста нет, каждый вызов должен нести `ctx` или транзакцию. Это переделка, не перенос, и равенство поведения доказать трудно. `docs/designs/fleet-toolchain.md` (D1, строка 40) уже отказал в смене среды исполнения, потому что она трогает LISTEN, advisory locks, RLS и подпись S3 «for no measured win». Перенос на Go трогает всё это снова и выбрасывает только что влитый `s3.ts`.

**С2. Исполнитель ставит Go перед выбором cgo.**

- `crates/executor/Cargo.toml:7` — `rusqlite` с `bundled` (SQLite на C). `docs/executor-build.md:24` опирается на WAL/FULL. `delegation.py:13` открывает тот же `journal.sqlite` из Python одновременно с исполнителем.
- `mattn/go-sqlite3` требует cgo и ломает сборку Mac с Linux. `modernc.org/sqlite` без cgo — большая зависимость; её блокировки рядом с пишущим Python и поведение fsync надо проверить.
- `crates/executor/src/native.rs:119-190` — `proc_pidinfo` и поиск `proc_signal_with_audittoken` через `dlsym`; `preview.rs:53` — `setrlimit` перед exec. Прямой формы на чистом Go для них, возможно, нет (не проверено). Linux-часть (`pidfd_open`, `pidfd_send_signal`, `native.rs:194-207`) доступна через `x/sys/unix`.

**С3. Отдельной цели Windows нет.** В исходниках Rust нет `cfg(windows)`; WSL определяется по строке ядра (`harness.rs:311-313`); везде `std::os::unix`, `killpg` (`main.rs:722`), `flock` (`:1035`), `O_NOFOLLOW` (`:771`). PTY не используется. Целей сборки две: darwin/arm64 и linux/amd64 (архитектуры не проверены). ConPTY, job objects и самообновление под Windows вне рамок, пока не нужен исполнитель под Windows без WSL. `deploy/` на части под Windows не проверяли.

**С4. Доставки исполнителя сегодня нет, и она не довод за Go.** CI собирает отладочный файл только для тестов (`.github/workflows/ci.yml:29,123`); публикуется только архив координатора (`:107-121`); `deploy/build-release.sh` — только координатор. На PDS18 исполнитель собирается на месте в `/home/fleet/runtime/executor-<sha>` (`docs/pds-codex-environment.md:9,29`), на Mac файл копируют и делают `launchctl kickstart` (`docs/agent-tools-inventory.md:104`). Юнита или plist исполнителя в репозитории нет. Сборку в CI и скачивание можно сделать для Rust сейчас: сборочная матрица с родным раннером macOS (так выпускают ripgrep и uv) или `cargo-zigbuild`. Требование «с одной Linux-машины» — ограничение, которое концепция наложила на себя сама.

**С5. Подпись macOS не продумана.** В CI нет задания под macOS и шага подписи (все задания на ubuntu). Скачанный файл darwin-arm64 нужно как минимум подписать ad-hoc. Делает ли это компоновщик Go при сборке с Linux — не проверено. Вопрос 6 из handoff (безопасность, проверка скачанного) концепция не закрывает.

**С6. «Python убран» — больше, чем скрипты.**

- Исполнитель встраивает MCP-серверы на Python и запускает `python3 -c` на хостах (`main.rs:405-409,444-447`, `profile.rs:167-211`).
- Координатор запускает `python3 connection_call.py` (`packages/coordinator/pipelines.ts:69`) и поставляет `delivery_worker.py`.
- `deploy/infrastructure/origin_guard.py` — развёрнутая служба в своём venv.
- Все 13 тестов протокола исполнителя написаны на Python (`tests/executor/*.py`) и в CI не запускаются.
- Решение: сделать серверы подкомандами исполнителя (`fleet-executor mcp delegation`). Это одинаково работает в Rust и убирает незакреплённый Python с хостов без выбора Go.

**С7. Выигрыш по цепочке поставок мал и не измерен.** У исполнителя 5 прямых crate (`Cargo.toml:6-10`). В рабочих зависимостях Node — `fastify`, `@fastify/static`, `pg`, `@clickhouse/client` плюс приложение (`package.json:16-25`). pnpm, esbuild, TypeScript и Playwright остаются для приложения при любом исходе. Go добавляет `pgx`, драйвер SQLite, клиент ClickHouse, sqlc и генератор Go -> TypeScript. Уходит cargo, но не тот менеджер пакетов, которому владелец не доверяет. `@clickhouse/client`, возможно, не используется в `packages/coordinator/**/*.ts` — проверяющие разошлись, нужно уточнить.

**С8. Слабая типизация идёт от хранилища, а не от языка.** Проверяющие насчитали 470–501 совпадение `any` только в `packages/coordinator` против 123 в концепции (методы подсчёта разные, точное число не установлено). Скопления: `app.ts` около 100, `lab/experiments.ts` 49, `agent-tools.ts` 47, `pipelines.ts` 34. Само хранилище возвращает `any[]` (`store.ts:101`). Go поверх того же `jsonb` даст `map[string]any`.

**С9. Go не обгонит то, что уже измерено.** Сборка 2,3 с, проверка типов 0,25 с (`fleet-toolchain.md:22-25,88`). 52 с тестов — устройство тестов, не язык; ни один вариант концепции этот пункт напрямую не решает (вопрос 3 из handoff открыт). Холодная сборка Rust 14,7 с измерена на crate с пятью зависимостями; Rust-координатор с асинхронным HTTP и Postgres надо мерить, а не выводить. Настоящая цена Rust в параллельных деревьях — блокировка общего каталога `target` (`fleet-toolchain.md:46`).

**С10. Правила «CI падает» спорят с «помогает и не блокирует».** Падение на тесте без ссылки на требование — придуманный предел; агенты обойдут его произвольными ссылками. В репозитории принято предупреждать: «Use-case drift (warning only)» (`ci.yml:31-35`). Для проверки расхождения есть вариант без запрета: не хранить сгенерированные файлы в git, а создавать их при сборке — тогда расхождению негде возникнуть.

**С11. Удаление старых тестов без доказательства, что новые ловят ошибки.** 41 файл тестов импортирует внутренности (`tests/coordinator/*.test.ts`) и против координатора на Go не запустится. Новые тесты — единственное доказательство равенства поведения, но ничто не показывает, что они что-то ловят. Не сказано, что делать с поведением, которое покрыто только старыми тестами.

**С12. Что пропускает правило «только снаружи».** Поведение ролей RLS, тестовые векторы SigV4, восстановление после сбоя, очистка потомков процесса, безопасная работа с символическими ссылками в исполнителе. Не сказано, считаются ли «снаружи» настоящий Postgres с ролями и поддельный процесс harness и остаются ли тесты приложения на Playwright. Handoff (строка 58) требует сохранить тесты RLS. Язык самих тестов не назван: тесты на Go сместят сравнение и пропадут, если победит Rust.

**С13. Порядок переноса при активной работе в main.** Другие работники сейчас правят `schema.sql` и `app.ts` (handoff, строка 66). Порядок в концепции не задан.

### Мелочи и неясные слова

- «seam» — определить один раз: место, где две программы обмениваются данными.
- «one coordinator slice», «executor protocol» — назвать точные маршруты, таблицы и поведение исполнителя. В репозитории протокол называется «host protocol (poll, message, receipt)».
- «one file per platform» — встроены ли `schema.sql` и `config/` или лежат рядом; какие архитектуры.
- «downloaded by hosts» — откуда, какая версия, кто запускает, как проверяется. `docs/executor-build.md:24`: «no SSH deployment exists».
- «all glue scripts» — перечислить каждый файл и его судьбу, включая `.sh` и `.mjs`.
- «differs from its source» — писать: CI создаёт файл заново и сообщает, если сохранённый изменился.
- Отношение к `docs/designs/fleet-toolchain.md` (статус «implemented») не задано: перенос на Go отменяет D1–D4 для координатора.

## Goals vs. Non-Goals

**Цели (в порядке владельца) и чем они закрываются**

| Цель | Что в концепции её касается | Замечание |
| --- | --- | --- |
| Быстрая разработка агентами в параллельных деревьях | Только замер в пробном переносе | Главная цель не измеряется: нет замера «от правки до зелёных тестов» и числа циклов агента |
| Быстрая сборка и доставка | Сборка в CI, скачивание хостами | Не зависит от языка |
| Малая цепочка поставок | Удаление Python и Rust | Не измерено; pnpm остаётся |
| Малое потребление ресурсов | Замеры памяти и размера | Низшая цель, решать исход не должна |
| Один источник на каждом стыке | Генерируемые типы | Источник выбран неверно (Б1) |

Ни к одной цели не привязаны: падение CI на тесте без ссылки и запрет тестов внутренних функций.

**Не цели**

- Исполнитель под Windows без WSL (ConPTY, job objects).
- Новый метод тестирования: действует `engineering/testing.md` из specq, отдельного исследования нет.
- Поддержка старого кода, данных и старых тестов.
- Смена стека браузерного приложения.
- Новые пределы и запреты в CI.
- Решение о языке до замеров.

## Alternatives Weighed

**Язык**

| Вариант | Какой цели служит лучше | Слабое место | Замер, который отделяет его от Go |
| --- | --- | --- | --- |
| A. Оставить TypeScript и Rust; добавить генерируемые контракты, сборку исполнителя в CI, подкоманды вместо Python, запрет `any` на стыках | Наименьшая цена, один источник | Два языка серверной части остаются | Сколько посеянных ошибок стыка поймано; если столько же, сколько у Go, перенос даёт только доставку |
| B. Go для координатора и исполнителя (концепция) | Сборка под все цели, один язык | cgo для SQLite и вызовов macOS; переделка транзакций; `map[string]any` | — |
| C. Go-координатор, Rust-исполнитель остаётся | Доставка без переноса исполнителя | Два языка, перенос транзакций остаётся | Трудоёмкость переноса исполнителя; путь сборки под Mac |
| D. Rust везде | Строгость, память, скорость работы | Блокировка общего `target`, холодная сборка координатора неизвестна | Время N деревьев одновременно; холодная сборка координатора |
| E. TypeScript везде | Самый быстрый цикл правки, один язык | Память и размер исполнителя на хостах; Node SEA уже отклонён (`fleet-toolchain.md:64`) | Память и размер на хосте |

Вариант A должен быть базой сравнения. Иначе Go получит в заслугу то, что даёт не язык.

**Источник типов**

| Вариант | За | Против |
| --- | --- | --- |
| `schema.sql` -> sqlc -> Go -> TypeScript (концепция) | Один файл | Не описывает события, API и протокол хостов (Б1, Б2) |
| JSON Schema в `contracts/` для API, событий и протокола; `schema.sql` только для строк | Уже применяется для `lab-config.json`; `prototype.json` даёт примеры для старта; генераторы есть для Go, Rust и TypeScript; работает без смены языка | Второй источник рядом со схемой базы |
| protobuf с buf или OpenAPI с oapi-codegen | Проверенные решения (Buf, Connect) | Ещё один язык контракта и инструмент |
| Структуры Go как источник, tygo для TypeScript | Самый лёгкий, если победит Go | Привязан к Go; не годится для варианта A |
| TypeSpec | — | Никто из проверяющих не привёл доводов за него |

Большинство проверяющих сошлись на двух источниках, каждый владеет своим стыком: `schema.sql` — строками базы, одна схема протокола — API, событиями и обменом с хостами. sqlc, если вообще нужен, — только для запросов.

**Доставка исполнителя на Mac:** сборка Go с Linux без cgo; родной раннер macOS в матрице CI; `cargo-zigbuild`. Мерить время и успех сборки darwin-arm64 каждым путём, включая SQLite.

**Правило о тестах:** падение CI (концепция) против отчёта в выводе CI о покрытии требований и тестах без ссылки. Второе соответствует правилам владельца и принятому в репозитории.

## Key Decisions & Staging for Next Steps

**Принято владельцем 2026-11-10:** порядок «сначала L2–L4 на текущем стеке, потом пробный перенос L1 на Go и на Rust против этой новой базы». Язык меняется, только если выигрыш остаётся после L2–L4.

**Шаг 0 (принят владельцем 2026-11-10): довести правила до агентов. Выполняется до шагов ниже.**

Отдельное исследование метода тестирования отменено: метод уже записан в общих правилах specq (`engineering/testing.md`: наименьший набор тестов, без целей по покрытию и числу тестов, постоянный тест называет требование и риск, проект задаёт одну команду проверки и бюджет времени). Не работает доставка этих правил:

**Какой результат отклоняет Go** (сравнения с измеренным текущим стеком, без придуманных чисел)

- Сборка без cgo не покрывает SQLite или вызовы ядра macOS из `native.rs`.
- Перенесённый слой транзакций не проходит тесты на параллельность и сериализацию.
- Цикл «от правки до зелёного» на срезе не быстрее сегодняшнего (проверка типов плюс тесты того же среза) на той же машине.
- Rust достигает зелёного за меньшее число циклов агента при равном или лучшем времени цикла.
- Число модулей не уменьшается.
- Go ловит столько же посеянных ошибок стыка, сколько вариант A: тогда перенос покупает только доставку, а она доступна и без него.
- Если ни Go, ни Rust не обгоняют базу по циклу — оставить TypeScript и Rust, сделать только L2–L4.

Размер файла и память служат низшей цели и исход не решают.
