# Project context

Use a project repository as the default home for instructions, requirements, pipeline definitions and small materials. Large assets may remain elsewhere, referenced from project files or task inputs. This does not require a code repository or a dedicated source-management interface.

Tasks expose their inputs and results; pipelines expose their definitions and settings. Supply each step with relevant instructions and materials, with other context discoverable as needed. Context selection does not grant or restrict access.

Ordinary sessions support one-off work and experiments without a predefined pipeline. Formalize a reusable method when repetition warrants it; update an existing method where applicable. Repeated work uses accessible definitions rather than requiring reconstruction from conversation history.

Retaining execution history does not make an experiment a project standard. Changes to project rules and recommended methods remain explicit actions. No mandatory process captures every conversational decision as a rule.

Validate this baseline through real projects before adding material catalogues or prescribing a project directory structure.
