# Coordinator

## Overview

`coordinator` is Fleet's loopback HTTP service. It applies the PostgreSQL schema, loads the people projection, exposes browser and host operations, serves the SSE change stream, and starts background reconciliation passes. The service owns coordination state; executors and the gateway report through its host-facing API rather than writing the database directly.

The component groups its implementation by domain: projects, tasks, sessions and executions; versioned definitions and pipelines; hosts, accounts, connections and limits; artifacts and S3 storage; Lab evaluation; delivery, telemetry and watch passes. Typed public contracts live in the sibling [`../contract`](../contract) package.

## Interface

- [`bugsink.go`](bugsink.go) owns Fleet's part of error tracking ([error tracking](../../docs/designs/fleet-error-tracking.md)): `POST /api/errors` (a `rawRoute`: the app's credential check, at most 1 MiB, only an envelope for `FLEET_BUGSINK_WEB_DSN` host and project, each event's user replaced by the actor, forwarded to `FLEET_BUGSINK_INGEST`); `POST /api/bugsink/alert/{secret}` (Bugsink's webhook, secret from `FLEET_BUGSINK_ALERT_SECRET_FILE`: a new, regressed or unmuted issue opens the owner problem `problem:bugsink:<issue>` with fixed text, in the project whose `errors.bugsink` names the Bugsink project); and the `bugsink-resolved` pass, which closes a problem once the `bugsink` connection's `issue_get` reports the issue resolved or gone. Each is off while its setting is unset. Unexpected 500s and pass failures and panics go to Bugsink through [`errtrack`](../errtrack/README.md) with `FLEET_BUGSINK_DSN`.
- [`cleanup.go`](cleanup.go) owns delete and purge ([system management](../../docs/designs/fleet-system-management.md#archive-delete-purge)) over one reference map (`referenceMap`: every column that names an object, with whether its row goes with the object, keeps it, or neither; `TestReferenceMapCoversSchema` fails on an unlisted `*_id` or foreign-key column). `object_delete {kind: project|experiment, id, preview}` (owner, long) computes the cascade (the root closed over the owning columns: tasks, executions and their child runs, sessions, experiments, questions, artifacts) for the preview and again for the confirm, and refuses (409) while a live row outside it keeps one of its objects (another experiment's score citing a trial); the confirm cancels running pipeline runs, stops agent runs (`stopDetail` `deleted`), revokes run tokens, withdraws open questions, queues worktree teardowns, drops the object's budgets, sets `tombstoned_at` on the cascade (for an experiment also on its scores, notes and the documents of its trials) and, for a project, `definition.deleted_at` and `retired_at`, removes its unused connections, and writes a `setting-change` audit row. `system_purge {preview, kinds?}` (owner, long) removes removed hosts ([`host_remove.go`](host_remove.go)), then each tombstoned experiment, then project, that no live row outside its cascade keeps and no pending command names (every root of every kind checked before any goes, so the confirm removes what the preview lists), in `purgeOrder` in its own transaction with its audit row; a purged project keeps its definition row (`purged_at`), so its id is never reused. Each kept id comes with its reason (`kept[].reasons`: the first live row that keeps it, `"<table>.<column> by <kind> <id>"`, or a pending command of a live host); a pending command of a removed or purged host never blocks and is settled (`stopDetail` `host-removed`), and delete sends no teardown to a removed host. A call stops starting work after `purgeBudget` (60 s, under the site proxy's 100 s), lists the rest as `deferred` and answers `more: true`. The store objects no remaining artifact shares and the removed executions' ClickHouse spans become `purge-task` documents, run after the commit and retried by the next purge (`retryLater`). An object is deleted under its object lock (`objectLock`) after checking no copy on its store maps to it again; `artifactReserve` takes that lock for its copy inserts and `writeObject` in its caller's transaction (so `saveObject`, in its own transaction without the GLOBAL lock, and the Lab example writers write or check the object under it); a deduplicated copy is rechecked under it and the upload stores its own bytes when the object went. Rows a host writes later for a tombstoned execution are born tombstoned (migration 67 trigger).
- [`versions.go`](versions.go) exposes `system_versions`: installed and offered releases, the selected UI, RLS-visible hosts (with `pollError` while their polls fail) and timestamped asynchronous gateway probes. Missing release comparisons and pending probes remain unknown.
- [`host_poll_health.go`](host_poll_health.go) records a host's failed polls on the server, since the executor cannot report them: any non-2xx poll answer but a removed host (410) or a request that left sets `pollError {status, reason, message, since, at}` in the host's observation (reason: the error's `reason` code or `http_<status>`; message cut to 300 characters; `since` kept across failures and across observation flushes while failures come less than 5 minutes apart; `at`, the last failure, rewritten at most once a minute when nothing else changes; a repeat within that minute costs no transaction; a host never observed gets no record). A failure while the request is already gone (a host restarting mid long-poll) is not recorded. `hosts_list` and `system_versions` show it while the host polls (a poll counts as seen before its body is read; not once the host is stale). After 2 minutes of failures it opens the owner problem `problem:host-poll:<host>` (fixed text: host id and the reason code of the failure that reached 2 minutes) under GLOBAL and the host's lock, only while the record is still there. The next successful poll clears the record and withdraws the problem under the host's lock only (never GLOBAL), unless a failure was noted meanwhile; a host known clean costs nothing; `hosts_remove` withdraws the problem too. A host that stops polling keeps its problem until it polls successfully or is removed. A poll 4xx other than 400, 401 and 410 goes to Bugsink with tags `host`, `status` and `reason`, once per run of one failure. In [`pollReadyCommands`](host_poll.go) each pending command is prepared under its own savepoint (`pollCommandRefusal`): a command whose preparation fails for a lasting reason of its own (`HTTPError` 403, 404 or 410) is rolled back and stopped (`stopDetail` `refused: <message>` for a 403 such as a pipeline authority refusal, else `handoff failed: ...`), never handed over; a pipeline start or script whose plan entry is still `prepared` (no host has seen it) also cancels its execution with that reason and wakes the dispatch pass. Any other failure (a conflict, a race, a busy dependency, any other database error, which may be the coordinator's own bug) leaves the command pending for the next poll, with one log line and one Bugsink event per command and error class (status and reason, or SQLSTATE; `commandWaits`, at most 4096 entries, an entry dropped when its command prepares or stops); serialization failures, deadlocks, connection errors and statement timeouts (classes 40, 08, 57) still fail the poll for a retry. The rest of the poll proceeds in both first cases. The failure record's status and message are what `errorAnswer` (`main.go`, shared with `writeError`) answered the host.

- [`main`](./main.go) starts `App` after migration and serves only on `127.0.0.1`; [`App.routes`](./registry.go) is the HTTP entry point. [`ops.go`](./ops.go) registers named operations and HTTP routes, applies request decoding, authorization and transactions.
- [`authorize`](./main.go) distinguishes host-secret calls under `/api/hosts/` from browser calls carrying a browser secret and `X-Fleet-Person`; [`checkOrigin`](./browser_checks.go) applies the browser-origin check.
- [`Store.Tx`](./store.go) is the database boundary. Both `Store` pools (every request, processor and read connection) run with `jit=off`: its statements are short indexed lookups, and JIT compilation (100+ ms) dominated them whenever an estimate crossed `jit_above_cost`. [`event_batch.go`](./event_batch.go) batches transport validation and inserts; after a complete closing event commits, chunk payloads are replaced by immutable retry hash/sequence identities. [`schema.sql`](./schema.sql) defines documents, tasks, executions, questions, artifacts, stores, definitions and the row-level security policies they use.
- [`serveStream`](./stream.go) provides the server-sent event stream. [`Broadcast`](./stream.go) listens for PostgreSQL notifications; [`stream_shared.go`](./stream_shared.go) owns a coalesced XID-ordered ring and shares current identity-scoped RLS batches between tabs. It prunes change rows older than 24 hours in bounded batches.
- Setting-change audit targets are captured into the same committed `change` row from the audit's NEW/OLD data and exported as optional `settingTarget`; legacy rows stay null. The feed adds no per-change lookup or actor-based target inference. Existing XID ordering, shared ring, viewer filtering and RLS decide visibility before serialization. Definition changes retain canonical `kind/id` IDs.
- [`pipelineStart`](./pipelines.go), [`pipelineAdvance`](./pipelines.go) and [`pipelineCancel`](./pipelines.go) create, progress and cancel pipeline runs; [`labReconcile`](./lab.go) progresses Lab experiments under their scope lock.
- [`artifactReserve`](./artifacts.go), [`artifactCommit`](./artifacts.go), [`artifactVerified`](./artifacts.go) and [`S3`](./s3.go) coordinate artifact upload, verification, replication and object-store access.
- [`hostsRegister`](./hosts.go), [`poll`](./host_poll.go), [`ingest`](./host_events.go), [`executionStop`](./executions.go) and [`dispatch`](./dispatch.go) connect registered hosts to execution lifecycle and command delivery: `/api/hosts/poll` holds only `"host:" + hostId`, debounces unchanged heartbeats (`30s`), supports `?wait` long-poll wakeups, and wakes/coordinates with [`startDispatchLoop`](./dispatch.go); [`writeTotals`](./records.go) persists leaf execution totals (`execution_totals`) on termination and `process.closed`; accepted native usage also normalizes confirmed running totals without process-resource inference, `fleet_change()` skips `tool_run` change rows, and `fleet_artifact_change()` skips no-op `store` updates.
- [`analyticsQuery`](./analytics.go) serves `analytics_query` and shared leaf-only resource rollups (`taskResourceRollup`, `sessionResourceRollup`, `boundaryResourcesMap`, `definitionUsageResources`, `projectResources`), keeping PostgreSQL RLS active, resolving per-leaf prices via `LATERAL` before grouping, and keeping multi-currency `(currency, basis)` `CostFigure[]` entries separated.

- [`resource_projection.go`](resource_projection.go) starts only with `FLEET_RESOURCE_PROCESSOR=on` (startup default off). One listener receives `fleet_resource_work`; a 100 ms recovery tick also advances durable work, builds and metadata jobs. Each pass coalesces at most 100 indexed work hints; executions with a captured clearing scope yield before that limit so they cannot occupy every slot. From the earliest unconsumed candidate, the single writer gathers every confidently same-project execution (at most 100) within that selected set, preserving per-project relative order across interleaved candidates. It does not fetch more work or wait to fill a cohort. Every selected ID is attempted once through selection before the existing build/metadata pass boundary; a failed cohort is retried in halves (`resourceBisectCohort`) and a single remaining leaf takes the bounded independent path. Uncertain/moving/NULL/multi-project scopes retain independent replacement. No source capture switch exists.
- [`wake_outbox.go`](wake_outbox.go) always dispatches durable notification intents, independently of resource flags. `fleet_change` comes from canonical change/artifact/summary triggers and people replacement; `fleet_resource_work` comes from source/metadata capture; `fleet_resource_summary` retains internal project publication payloads. Producers append immutable UUID/source-XID/channel/payload intents in the source transaction. A bounded1000-row `SKIP LOCKED` claim, coalesced `pg_notify` and deletion of only claimed UUIDs commit atomically. Rollback/restart retain intents; listeners still recover from the original durable rows and XID barriers. Full batches continue immediately and idle recovery checks run every100ms. This removes PostgreSQL NOTIFY's global commit lock from canonical source transactions without disabling notifications or source capture ([protocol](../../docs/designs/fleet-analytics.md#durable-notification-delivery)).

### Internal prepared-resource interfaces

| Helper | Contract |
|---|---|
| `resourceReplace(ctx, app, executionID)` | Claim immutable work UUIDs, read source/old contribution/frozen method in one SQL snapshot, check sorted project-then-execution locks, subtract/add support, publish header/revision and delete only claims atomically. A new scope retries the whole transaction; source rows are never locked. |
| `resourceReplaceBatch(ctx, app, executionIDs)` | At most 100 (one pass) confidently same-project leaves, complete canonical lock set before authoritative per-leaf claims/snapshots, independent valuation/support changes and one project publication. Exact UUID deletion and all leaves commit together; any SQL/scope failure rolls back the cohort, which is retried in halves down to the independent path. |
| `repairTotalsOwnership(ctx, app, executionID)` | Separate source repair: sorted project/execution advisory locks, parent row first, scope recheck, then align totals including NULL. Replacement leaves mismatches pending until repair. |
| `resourceBuildPage(ctx, app, projectID)` | One atomic page/checkpoint, at most 100 source IDs; clearing/scanning/draining/ready recovery. Finalization requires no pending scoped work or unresolved metadata coverage in its snapshot. |
| `resourceRebuild(ctx, app, projectID)` | Internal maintenance starts clearing and a new preparing epoch; retains all source work and frozen valuations. Ordinary replacements yield for every affected clearing scope. |
| `resourceMetadataPage(ctx, app, repairID)` | Atomic union scan of normalized old/new connection names and full account IDs; keeps repair scopes until enumeration and all seeded work drain. |
| `resourceReadPrepared(request, projectID)` | Call only after project authorization in a scoped `Store` read transaction. Reads the RLS-visible header/version, then maintenance-only progress through `unscoped`; both use the same repeatable-read snapshot. Missing projection is preparing. No source history, rebuild or expensive fallback. |
| `resourcePreparedHeader(request, projectID)` | Internal publication reducer over fixed metric/basis support, indexed extrema and maintained item counts; never enumerates tools, costs, prices or execution history. |

`ResourceContributionV1`, frozen `ResourceMethodV1` and `PreparedHeaderV1` derive from `contracts/ops-tasks.schema.json`. Money and credits stay exact decimal strings/PostgreSQL numeric internally; only the established header wire credits field converts to a number. A preparing contribution does not freeze a valuation before confirmed usage/time/model or a connection amount is available; the first eligible missing rate remains frozen. Support retains every tool and price reference. Version is `epoch:revision`, with revision retained as decimal text by the read seam; it is not source progress.

The initial sorted project-scope hint is one indexed maintenance read, without a separate read transaction; it is never authoritative. The cohort hint query materializes selected execution IDs, retained work IDs and matching captured scopes, then groups their canonical/totals/contribution/work union. Empty-queue statistics cannot turn the captured-scope lookup into one queue scan per selected leaf. Empty candidate lists do no database work. Internal scope-hint spans record candidate/returned counts and separate pool acquisition from query/decoding time without listing payloads or work UUIDs. Authoritative replacement spans record the actual number of claimed work UUIDs only after a successful claim read. The locked replacement claims due immutable work UUIDs and reads the source/frozen contribution/scopes in one statement snapshot, then verifies every observed scope before support writes. Existing build/summary rows use one joined phase check and summary lock; missing rows retain the initializer path. Scope expansion rolls back the whole transaction. Cohorts establish every leaf/project lock before claiming and do not expand locks in place; moving/NULL/multi-project or uncertain scopes use independent replacement. A failed cohort is not retried indefinitely as a cohort: its retained work returns to independent isolation/backoff, preserving project/metadata fairness and resolving uncertain COMMIT from durable state.

Support changes of every leaf in a replacement transaction are netted per project ([`resource_apply.go`](resource_apply.go)) and sent as one `pgx.Batch`: per table, an upsert for keys whose every component only grows, a delete for keys whose references reach zero and an update for the rest (CHECK constraints apply to an INSERT's proposed row before ON CONFLICT, so a losing key never takes the insert path). A cost key is netted only when the transaction only adds known amounts to it; any unknown amount or subtract keeps its per-contribution statements in order (inside the same batch), because a NULL value absorbs later sums until its row is deleted at the last reference and recreated. On a consistent ledger the result equals sequential per-contribution application (cost values keep numeric's scale, which cost items return as stored; metric sums may be stored trimmed, and every metric reader normalizes them) (a randomized PostgreSQL test compares both write paths with an independent simulation). Netting can no longer detect every corrupt-ledger case a lone subtract did: a missing row whose subtract and add cancel passes. A key whose net change is zero is not rewritten; `resource_reasons_merge` drops zero reason counts and rejects negative ones. An absent, unexpected metric without a missing reason has no support delta; measured zero, expected missing values and retained reasons still mutate support. A zero numeric amount never suppresses presence, expectation or reference changes. Tool/cost/price item-count updates occur only when the first support reference appears or the last disappears; calls, errors, exact amounts and reference multiplicities still change on every applicable contribution. Reading every batch result and closing it propagates every SQL error before replacement proceeds. The enclosing replacement transaction owns claims, authoritative per-leaf snapshots, the complete sorted lock set, exact support, contributions, publication and claim deletion. A SQL batch failure rolls the whole replacement transaction back. A confidently same-project cohort may contain up to 100 leaves and publish once; every leaf still retains its own frozen method and exact support. No concurrent project writer is introduced, and no source fact is considered consumed before confirmed COMMIT.

The three independent fixed-header reads use one ordered batch under the same project lock. Every result is consumed and a late SQL error aborts the replacement before publication.

`resourcePublish` updates the header/revision and appends an internal `fleet_resource_summary` wake intent atomically in one SQL statement. The revision trigger atomically appends project-filtered `resource_summary` changes to the existing XID/SSE transport; the always-on dispatcher emits their committed hints separately. `projects.go` owns the additive typed `project_detail`, `project_resources` and `project_resource_items` reads and startup `FLEET_RESOURCE_READS` flag (default off): disabled operations are unadvertised and return 503. The configuration reader is independent of stored header/progress and bounded C-order keyset pages; cursors bind epoch/scope/filter/position rather than publication revision. Large admitted tool tuples use stdlib zlib/base64url cursor v2 and typed packed tool positions; cursor v1 remains readable, and clients use optional item.position for large re-anchors within the unchanged HTTP body bound. Legacy `project_context` keeps its history query and live tariff selection. `resource.process`/`resource.replace` spans record duration, lock time, candidate count, fact size, failures and oldest pending age; source observation time remains unknown where not retained. Internal `resource.apply` spans (one per replacement transaction and project, carrying `apply_statements`) and `resource.publish` spans expose support/header write durations. Replacement records claim/snapshot return and confirmed transaction return timestamps. A `resource.batch` span owns a cohort transaction; per-leaf replacement spans share its confirmed commit endpoint and publication version, so their overlapping durations must not be summed as transaction wall time; publication-version metadata describes the SQL result until the enclosing transaction is confirmed. Successful prepared-read spans record only the returned version/state and project identifier, without row content.

## Invariants

- Pipeline steps persist their observed terminal `finishedAt` as `ended_at`; nonterminal/reopened steps clear it. Typed execution reads recover only valid retained terminal millisecond ends for older rows, without a database backfill or inference from duration/current time. Missing or malformed legacy timing stays unavailable. Pipeline containers remain excluded from leaf resource totals; reused-prefix timing keeps its original provenance.

- [`publication.go`](publication.go) is the bounded `publication` pipeline program, executed by the coordinator service under its existing filesystem authority. The configured `publication` role is recorded separately and receives no synthetic heartbeat. Only the two configured test-site projects can publish; the configured readback URL must match the current coordinator loopback port and project path (omitted port is equivalent only when the coordinator itself uses port 80), with no rerouting to another service; same-project stored artifacts are streamed and hashed, the durable immutable manifest fences replay, and the current pointer is selected atomically. Authenticated protected-route readback establishes success; failed verification restores the prior pointer only while the pointer still selects this attempt. Later publications are never overwritten by replay or cleanup. Pipeline cancellation serializes with the program and does not roll back a completed publication.

- [`accounts.go`](accounts.go) couples account-host connectivity to the actual inspection destination: a fresh eligible native execution host takes precedence, a configured inspector remains the permitted fallback, and observations must match the configured holder. Discovery inspects an existing registry without authenticating or moving credentials.

- [`execution_trace.go`](execution_trace.go) retains originating trace metadata in execution/queued-message records, records one durable dispatch edge per command, and supplies optional command run attribution; `telemetry_trace` resolves execution IDs under PostgreSQL RLS before querying spans.

- The service requires `FLEET_PEOPLE_FILE` and `FLEET_DATABASE_URL`; [`setPeople`](./main.go) requires exactly one owner and rejects duplicate people or conflicting service-token common names.
- HTTP request headers, bodies and idle connections have 10 s, 30 s and 90 s timeouts; streaming responses have no global write timeout.
- [`readBody`](./main.go) limits JSON request bodies to 1 MiB and host calls cannot name another `hostId`. Host requests carry no person identity.
- [`Store.Tx`](./store.go) and [`Store.TxLocks`](./store.go) use separate explicitly sized 16-connection read and write pools and give reads a repeatable-read snapshot; writes serialize in PostgreSQL via deduplicated, canonical-rank-sorted 64-bit `pg_advisory_xact_lock(hashtextextended(..., 0))` across `GLOBAL < dispatch < project:* < task:* < session:* < experiment:* < execution:* < host:* < usageKey:* < person-setting:*`, reject out-of-order lock acquisition, and retry serialization failures and deadlocks.
- Migration 67 adds a restrictive SELECT policy `live` to every project-owned table but the change feed and the resource tables: tombstoned rows and every row of a deleted project are invisible to every reader, the owner and the coordinator's own passes included, unless the transaction sets `fleet.deleted=on`. Only the executor-internal host routes set it (`deletedHostRoutes`: poll, receipts, events, spans; [`authorize`](./main.go), `showDeletedKey`), so the stop and teardown of deleted work are still delivered and their results land; every other host route (agent tools, project operations, child runs, artifact reads and transfers) reads as everyone does; delete and purge set it themselves.
- [`schema.sql`](./schema.sql) enables row-level security on project-owned state. [`scopeOf`](./main.go) and [`refreshRequestAccess`](./project_access.go) set the transaction's project/person scope; the owner uses the unrestricted scope.
- [`schema.sql`](./schema.sql) source triggers retain transactional `resource_work` and non-secret `resource_metadata_repair` for prepared summaries. Work identities never cascade with source deletion; maintenance tables use FORCE RLS. Parent execution ownership aligns totals atomically, including NULL; totals writers lock the parent first. The opt-in [`resource_projection.go`](resource_projection.go) processor maintains replaceable contributions, fixed-size headers and normalized support; prepared public reads require startup exposure and current project authorization ([contract](../../docs/designs/fleet-analytics.md#prepared-project-resources)).
- [`migrate`](./store.go) applies each `-- migration N` schema section once under the migration lock.
- [`definitionState`](./definitions.go) computes definition state from stored revisions and shipped repository content; [`reconcileDefinitions`](./definitions.go) records shipped content but does not move an edited head.
- [`taskTransition`](./tasks.go) enforces declared task transitions. [`artifactGate`](./executions.go) keeps an execution waiting until required artifacts satisfy its requirement, rather than treating missing artifacts as success.
- [`newS3`](./s3.go) refuses redirects for signed object-store requests; [`S3.send`](./s3.go) retries only selected transient statuses, throttling codes and network failures, up to three attempts.

## Side Effects

- Starts a loopback HTTP server, PostgreSQL listener and periodic passes through [`startAll`](./registry.go); writes telemetry through [`startTelemetry`](./telemetry.go).
- Mutates PostgreSQL state, emits `fleet_change` notifications, and may queue host commands. [`onEnd`](./store.go) delays registered filesystem effects until a transaction is known committed.
- Reads people, release/configuration and Lab files; [`connections.go`](./connections.go) can ingest gateway spool files and remove fully imported past-day files only after commit.
- Reads, writes, copies and deletes S3-compatible objects through [`S3`](./s3.go). Artifact deletion and retention routines keep tombstones and avoid deletion while a verified copy is unreachable.
- [`runChecks`](./lab.go) executes approved Lab check commands in a temporary directory; on Unix it kills the check process group after completion or cancellation.

## Verification

- Run: `cd go && go test ./coordinator`
- Build the executable: `cd go && CGO_ENABLED=0 go build -o bin/fleet-coordinator ./coordinator`
- For the repository-selected full gate, use the command in [`../../fleet.md`](../../fleet.md#verification); it requires the project test environment and is not a coordinator-only check.

## Finite pipeline plans

`pipeline_condition.go` owns the closed Boolean/enum grammar. `pipeline_plan.go` owns version-1 plan identity, revision fencing, selected execution references, current authority/handoff and canonical result/input bindings. `pipelines.go` compiles static v2 and conditional v3 definitions into that one model and projects internal observations from selected rows. Public plan reads do not reconstruct omitted work from generic execution lists. Old runtime formats require a clean start, without an adapter or state reset in source delivery.

`lab_assessment.go` captures fixed contained assessment bytes, materializes ordinary artifacts outside write locks and links exact evaluator/input/trial identities with the existing Lab score transaction. `lab_retry.go` verifies current-format selected command/process and artifact proof; missing proof conflicts and never authorizes provider replay. See [pipeline configuration](../../docs/configuration.md#pipeline-execution) and [Lab assessments](../../docs/designs/fleet-lab.md#conditional-plans-and-project-assessments).
