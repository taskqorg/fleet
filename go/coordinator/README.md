# Coordinator

## Overview

`coordinator` is Fleet's loopback HTTP service. It applies the PostgreSQL schema, loads the people projection, exposes browser and host operations, serves the SSE change stream, and starts background reconciliation passes. The service owns coordination state; executors and the gateway report through its host-facing API rather than writing the database directly.

The component groups its implementation by domain: projects, tasks, sessions and executions; versioned definitions and pipelines; hosts, accounts, connections and limits; artifacts and S3 storage; Lab evaluation; delivery, telemetry and watch passes. Typed public contracts live in the sibling [`../contract`](../contract) package.

Architecture standard: [docs/designs/fleet-standard.md](../../docs/designs/fleet-standard.md); rules checked by [design_rules_test.go](design_rules_test.go) ([DESIGN_RULES.md](DESIGN_RULES.md)).

## Interface

- [`people.go`](people.go) projects the private people file and serves the versioned owner-only Humans roster and entry mutations. [`people_cloudflare.go`](people_cloudflare.go) synchronizes the Cloudflare Access group, records intent and results in the People audit, and reads current email rules for the roster. [`personal_lab.go`](personal_lab.go) serves author-scoped drafts and architect-confirmed promotion of submitted shared pipeline references.

- [`bots.go`](bots.go), [`bots_runtime.go`](bots_runtime.go) and [`bot_states.go`](bot_states.go) own persistent bots: saved settings and project-scoped memory revisions, one stable Home conversation in Conversations (unattached to a single task, with standard input queue and sender provenance), shared wake admission (`bot_run`, scheduled daily wakes and `Needs you` triggers with durable `bot_wake_cursor` deduplication and self-origin exclusion), single active run admission, native continuation vs project-scoped handoff, `bot_pause`/`bot_stop` lifecycle controls, and `bot_runs` observability (`quiet`, `skipped`, `queued`, `failed`, `unconfirmed`). [`bot_avatar.go`](bot_avatar.go) owns a bot's avatar (`bot_avatar_set`, `bot_avatar_clear`): an image or video artifact of the bot's project, an optional still frame for lists and a glow colour; `bot_list`/`bot_get` carry it with `needsYou` (an open question in the Home conversation or active run, or a waiting run).

- [`bugsink.go`](bugsink.go) owns Fleet's part of error tracking ([error tracking](../../docs/designs/fleet-error-tracking.md)): `POST /api/errors` (a `rawRoute`: the app's credential check, at most 1 MiB, only an envelope for `FLEET_BUGSINK_WEB_DSN` host and project, each event's user replaced by the actor, forwarded to `FLEET_BUGSINK_INGEST`); `POST /api/bugsink/alert/{secret}` (Bugsink's webhook, secret from `FLEET_BUGSINK_ALERT_SECRET_FILE`: a new, regressed or unmuted issue opens the owner problem `problem:bugsink:<issue>` with fixed text, in the project whose `errors.bugsink` names the Bugsink project); and the `bugsink-resolved` pass, which closes a problem once the `bugsink` connection's `issue_get` reports the issue resolved or gone. Each is off while its setting is unset. Unexpected 500s and pass failures and panics go to Bugsink through [`errtrack`](../errtrack/README.md) with `FLEET_BUGSINK_DSN`.
- [`session_titles.go`](session_titles.go) owns conversation titles ([titles](../../docs/designs/fleet-conversations.md#titles)): `session_rename` (operation and agent tool) and the `session-titles` pass, which generates a missing title after the first reply through the `google-ai` gateway connection as a system read of the session's project, writes it only while none is set and backfills older sessions. The Conversations list and search (`sessions.go`, `search.go`) show the stored title, else the first message, and leave out host command sessions (`actor` program-worker).
- [`session_context.go`](session_context.go) serves `session_context` ([session view](../../docs/design-system/pages/session.md#data)), one read over state that already holds it: the plan (the session's `work_plan`, else its task's, through `workBoardGet`; one step per plan task with `done`), the watch timer (`watch.go`), the session's bot's automations (`botAutomations`; a bot the caller cannot see gives none) and the other board members with their state. `sessions_list` and `list_membership` rows carry `now` (`nowLine` in `sessions.go`): the first sentence of the newest agent text block of the session, else the attached task's title; the read is one backward probe of the partial index `event_agent_text` (migration 101, predicate `agentTextPath`) per listed row, evaluated after the page's LIMIT.
- [`person_visit.go`](person_visit.go) serves `person_visit {page}` ([Home](../../docs/design-system/pages/home.md#data)): the caller's visit before this one (`previousAt`) from `person_visit` (migration 100, one row per person and page); a person's call records this visit unless `record` is false, an agent's call only reads its director's.
- [`agent_context.go`](agent_context.go) records the fork route and source lineage on the child and the fork receipt. Context transfer uses the source's current project. A supplied next instruction submits the first child turn in the same transaction, with IDs for correlation on the operation span.
- [`cleanup.go`](cleanup.go) owns delete and purge ([system management](../../docs/designs/fleet-system-management.md#archive-delete-purge)) over one reference map (`references`: every column that names an object, with whether its row goes with the object, keeps it, or neither: each foreign key derived from the schema, `referenceKeys` (to an object table: owned under `ON DELETE CASCADE`, kept otherwise; to any other table: no object), and `referenceMap` for every other column and the keys it treats otherwise; `TestReferenceMapCoversSchema` fails on an unlisted `*_id` or foreign-key column). Its statements are assembled in [`sql_builder.go`](sql_builder.go) from the map's tables and columns; the fixed ones are typed queries ([`queries/cleanup.sql`](queries/cleanup.sql)). `object_delete {kind: project|experiment|task|session, id, preview}` (owner, long) computes the cascade (the root closed over the owning columns: tasks, executions and their child runs, sessions, experiments, questions, artifacts; a session's executions go with it, and a session whose executions ran for a live task is refused) for the preview and again for the confirm, and refuses (409) while a live row outside it keeps one of its objects (another experiment's score citing a trial); the confirm cancels running pipeline runs, stops agent runs (`stopDetail` `deleted`), revokes run tokens, withdraws open questions, queues worktree teardowns, drops the object's budgets, sets `tombstoned_at` on the cascade (for an experiment also on its scores, notes and the rows of its trials) and, for a project, `definition.deleted_at` and `retired_at`, removes its unused connections, and writes an audit row (`audit_log`, through [`audit()`](audit.go)). `system_purge {preview, kinds?}` (owner, long) removes removed hosts ([`host_remove.go`](host_remove.go)), then the tombstoned experiments and projects, in one random order per call, that no live row outside their cascade keeps and no pending command of a live host names (every root checked before any goes, so the confirm removes what the preview lists unless the preview answered `more`), in `purgeOrder` in its own transaction with its audit row; a purged project keeps its definition row (`purged_at`), so its id is never reused. Each kept id comes with its reason (`kept[].reasons`: the first live row that keeps it, `"<table>.<column> by <kind> <id>"`, or a pending command of a live host); a pending command of a removed or unknown host never blocks and goes with the object, and `teardownCommand` and connection removal queue nothing for a removed host. Span deletions of all purge tasks go in batched statements. A call stops starting work after `purgeBudget` (60 s, under the site proxy's 100 s), lists the rest as `deferred` and answers `more: true`. The store objects no remaining artifact shares and the removed executions' ClickHouse spans become `purge_task` rows, run after the commit and retried by the next purge (`retryLater`). An object is deleted under its object lock (`objectLock`) after checking no copy on its store maps to it again; `artifactReserve` takes that lock for its copy inserts and `writeObject` in its caller's transaction (so `saveObject`, in its own transaction without the GLOBAL lock, and the Lab example writers write or check the object under it); a deduplicated copy is rechecked under it and the upload stores its own bytes when the object went. Rows a host writes later for a tombstoned execution are born tombstoned (migration 67 trigger). [`definition_delete`](definitions_write.go) (owner) retires and marks deleted an agent or pipeline that is store-only or repository-deleted and that nothing uses (no definition names it, no unfinished execution pins it, no live Lab experiment runs it); its row and revisions stay, so the id is never reused, and `headOf` and the reads skip it.
- [`presets.go`](presets.go) owns session presets ([start a conversation](../../docs/designs/fleet-conversations.md#start-a-conversation)): the system presets, validation of a project's `settings.presets`, resolution to a profile (the project's role, else the preset's system profile) and `session_presets`; `sessionStart` (`agent.go`) applies a preset's profile, access, branch and starter, and dispatch places read or branchless starts only on hosts reporting `start-access-v1` and sends `readOnly`, `branch: false` and the starter with each start.
- [`hostsListReply`](hosts.go) adds per host `runs` (the caller's visible preparing and running executions, oldest start first: the order Live fills slot tiles, `hostRuns`) and `load` (the latest poll or heartbeat reading via `effectiveHostLoad`, with `diskFree` kept from heartbeat spans, only while the host polls and the reading is under `hostLoadStaleMs`). Execution rows (`executions_list`) and bot runs (`bot_runs`) carry `failure`, the stored problem code in plain words from `contract.PlainCause`.
- [`entity_card.go`](entity_card.go) exposes `entity_card` (also an agent tool): a card summary of one entity by D17 code (results by their `R` code; a bot's `B` code resolves through `entity_resolve` only) (old codes resolve, `resolveCodes`) or by kind and id, for tasks, questions, conversations, executions, results, experiments, projects, hosts, agents, pipelines, pull requests (the delivery pass under `deliveryStatus`'s visibility, then the fleet repository's delivery history under `deliveryMay`) and releases (known to the pass or history or run by a host or the site; hosts counted for full access only); each kind reads its own rows under row-level security and its list's gate (definitions and experiments for architects), so unknown and forbidden both answer 404 ([entity card](../../docs/design-system/controls/entity-card.md)).
- [`board.go`](board.go) owns the Swarm work-board operations ([Fleet Swarm](../../docs/designs/fleet-swarm.md)): `work_plan_set` (upserts `work_plan` for `(scopeKind, scopeId)`, increments `version`, validates `threads[]`/`tasks[]` under `board:<scopeKind>:<scopeId>`), `board_post` (appends `board_message` with monotonic `seq` under `board:<scopeKind>:<scopeId>`, parses `@mentions`, resolves `wakeTargets` from `work_plan` and prior posters), `board_read` (cursor/filtered reads under RLS), and `work_board_get` (unified `{ plan, roster, messages, summary }` joining live `session`, `execution`, `execution_totals`, and `execution_spend`).
- [`versions.go`](versions.go) exposes `system_versions`: installed and offered releases, the selected UI, RLS-visible hosts (with `pollError` while their polls fail, and `pollProblem` once they have failed long enough to open its owner problem) and timestamped asynchronous gateway probes (a failed probe is repeated at once, so unreachable means both failed). Missing release comparisons and pending probes remain unknown.
- [`host_poll_health.go`](host_poll_health.go) records a host's failed polls on the server, since the executor cannot report them: any non-2xx poll answer but a removed host (410) or a request that left sets `pollError {status, reason, message, since, at}` in the host's observation (reason: the error's `reason` code or `http_<status>`; message cut to 300 characters; `since` kept across failures and across observation flushes while failures come less than 5 minutes apart; `at`, the last failure, rewritten at most once a minute when nothing else changes; a repeat within that minute costs no transaction; a host never observed gets no record). A failure while the request is already gone (a host restarting mid long-poll) is not recorded. `hosts_list` and `system_versions` show it while the host polls (a poll counts as seen before its body is read; not once the host is stale). After 2 minutes of failures it opens the owner problem `problem:host-poll:<host>` (fixed text: host id and the reason code of the failure that reached 2 minutes) under GLOBAL and the host's lock, only while the record is still there. The next successful poll clears the record and withdraws the problem under the host's lock only (never GLOBAL), unless a failure was noted meanwhile; a host known clean costs nothing; `hosts_remove` withdraws the problem too. A host that stops polling keeps its problem until it polls successfully or is removed. A poll 4xx other than 400, 401 and 410 goes to Bugsink with tags `host`, `status` and `reason`, once per run of one failure. In [`pollReadyCommands`](host_poll.go) each pending command is prepared under its own savepoint (`pollCommandRefusal`): a command whose preparation fails for a lasting reason of its own (`HTTPError` 403, 404 or 410) is rolled back and stopped (`stopDetail` `refused: <message>` for a 403 such as a pipeline authority refusal, else `handoff failed: ...`), never handed over; a pipeline start or script whose plan entry is still `prepared` (no host has seen it) also cancels its execution with that reason and wakes the dispatch pass. Any other failure (a conflict, a race, a busy dependency, any other database error, which may be the coordinator's own bug) leaves the command pending for the next poll, with one log line and one Bugsink event per command and error class (status and reason, or SQLSTATE; `commandWaits`, at most 4096 entries, an entry dropped when its command prepares or stops); serialization failures, deadlocks, connection errors and statement timeouts (classes 40, 08, 57) still fail the poll for a retry. The rest of the poll proceeds in both first cases. The failure record's status and message are what `errorAnswer` (`main.go`, shared with `writeError`) answered the host.

A viewer (roles `["viewer"]` only, project grants only; `isViewer` in [people.go](people.go)) may make GET requests and read operations (`read: true`); `viewerMay` answers 403 to everything else before it runs ([wall viewer](../../docs/designs/fleet-people-access.md#wall-viewer)).
- [`Store.Read` and `Store.Write`](./tx.go) are the transaction entry points of the [standard](../../docs/designs/fleet-standard.md) (S3): a read snapshot, or a write holding the entity locks the caller names; inside a transaction already open for the request they join it (a write acquires its locks there). Typed queries run through `q.db()`, package [`db`](./db) that sqlc generates from [`queries/<area>.sql`](./queries) ([`sqlc.yaml`](./sqlc.yaml), `pnpm run go:sqlc`) over `db/schema.sql`, which `TestMigrationSqlcSchema` keeps equal to the migrated schema. `afterCommit` and `afterRollback` run effects only after the transaction commits or rolls back; only writes holding `GLOBAL` fence and invalidate the auth cache ([`work_kit.go`](work_kit.go) uses `store.readOnce`/`store.writeOnce` for single-attempt queue steps and [`wake_outbox.go`](wake_outbox.go) uses `pgx.BeginTxFunc` directly so empty recovery checks do not open `Store` transactions).
- [`Store`](./store.go) is the database boundary. Both `Store` pools (every request, processor and read connection) run with `jit=off`: its statements are short indexed lookups, and JIT compilation (100+ ms) dominated them whenever an estimate crossed `jit_above_cost`. [`event_batch.go`](./event_batch.go) batches transport validation and inserts; after a complete closing event commits, chunk payloads are replaced by immutable retry hash/sequence identities. [`schema.sql`](./schema.sql) holds the numbered migrations: the tables of tasks, executions, questions, artifacts, stores, definitions and the rest (the `document` table went in migration 83). Every function, trigger and policy has its one current definition in [`schema/`](./schema) (`functions.sql`, `triggers.sql`, `policies.sql` with each table's row-level security switches); from migration 83 on a migration changes only tables.
- [`serveStream`](./stream.go) provides the server-sent event stream. [`Broadcast`](./stream.go) listens for PostgreSQL notifications; [`stream_shared.go`](./stream_shared.go) owns a coalesced XID-ordered ring and shares current identity-scoped RLS batches between tabs. It prunes change rows older than 24 hours in bounded batches.

The feed adds no per-change lookup or actor-based target inference. Existing XID ordering, shared ring, viewer filtering and RLS decide visibility before serialization. Definition changes retain canonical `kind/id` IDs.

- [`artifactReserve`](./artifacts.go), [`artifactCommit`](./artifacts.go), [`artifactVerified`](./artifacts.go) and [`S3`](./s3.go) coordinate artifact upload, verification, replication and object-store access.
- [`uploads.go`](./uploads.go) takes operator uploads (message attachments): `artifact_upload_begin` checks the session or project grant, starts a store multipart upload on a staging key and records an `upload` row in the person's scope (owner, parts, running SHA-256); `PUT /api/uploads/{id}` (a `rawRoute` with the app's credential check, only the person who began it, a 15-minute read deadline) sends each 8 MiB part of the grid, in order (409 with `received` otherwise), straight to the store; the last part completes it, copies it to its content key (`promote`, shared with `artifactVerified`) and records a stored `attachment` artifact with its verified copy. Nothing is spooled on the coordinator. [`attachments.go`](./attachments.go) checks the `attachments` of `message_send` and `session_start` (stored, same project as the session, readable in scope, an upload of no or this conversation), attaches an upload to the session, cleans names (`attachmentName`), and turns them into start-command `inputs` and `attachments` under `attachments/<execution>/` ([Attachments](../../docs/designs/fleet-conversations.md#attachments)).
- [`hostsRegister`](./hosts.go), [`poll`](./host_poll.go), [`ingest`](./host_events.go), [`executionStop`](./executions.go), [`forgeReviewRoute`](./forge_review.go) and [`dispatch`](./dispatch.go) connect registered hosts to execution lifecycle and command delivery. Every `/api/hosts/` route is registered by [`hostRoute`](./host_routes.go) on its `contract.Route<Name>` (request decoded as the route's `decode` says, reply its contract type; the poll's health is observed around its decoding, `hostRouteObserved`); `forgeReviewRoute` verifies project/host/actor grants, stored review artifact provenance and exact-SHA text reference before writing an `audit_log` row for `project-forge` `code_review`; a poll answers `contract.PollReply` with each command converted to `contract.Command` (a stored command that does not fit stays pending and is reported once), and dispatch and poll skip a host through the one gate `contract.MissingCapability`. `/api/hosts/poll` holds only `"host:" + hostId`, debounces unchanged heartbeats (`30s`), updates live `hostLoadObservation` (also fed by `host.heartbeat` spans in [`telemetry.go`](./telemetry.go)) without per-poll DB churn (flushing and waking dispatch immediately on overload transitions), supports `?wait` long-poll wakeups, and wakes/coordinates with [`startDispatchLoop`](./dispatch.go); `rankCandidates` enforces host load/memory backpressure (`load1 > cpus` or `memFree < 5% memTotal`), active execution concurrency limits (`host.maxConcurrent`, exposed as `hosts_list.slots`, or observed `cpus` when unset; `hosts_list.slotLimit` is that effective limit), and skips a host whose poll reports `update.state = "pending"` for a release newer than its `version` (its executor drains and admits no start) a continuation of a session whose last started run was on that host waits for it unplaced for up to 15 minutes (`continuationHostWait`), then moves; a run placed on another host than its last one starts a fresh native session (`nativeFor`) with a `host_move` context handoff, all with `waitReason = "placement"` visibility. [`writeTotals`](./executions.go) persists leaf execution totals (`execution_totals`) on termination and `process.closed`; accepted native usage also normalizes confirmed running totals without process-resource inference, `fleet_change()` skips `tool_run` change rows, and `fleet_artifact_change()` skips no-op `store` updates. [`reconcileLostExecutions`](./executions.go) and owner-only `executions_reconcile` safely reconcile dead/finished executions with no live worker process (`outbox.failed`, `process.closed`, terminal command, `teardown`, removed host, or omitted from live `activeExecutions`, excluding `waiting` for `artifacts` and unpicked `preparing` runs) to `failed`/`unconfirmed`/`unknown:abandoned` with `audit_log` provenance, and `ingest` keeps `teardown`/`outbox.failed` batches from marking abandoned runs `confirmed`. [`runPlacement`](./placement.go) batches stored artifact copy lookups (`DispStoredArtifactCopies`) and caches per-project locations, valid rules, and `DispRuleConfirmed` checks once per pass.
- [`price_refresh`](price_refresh.go) compares the append-only price catalog against [official provider documents](../../docs/designs/fleet-analytics.md#provider-pricing-refresh). [Provider parsers](provider_prices.go) extract exact Standard model rates and report unsupported or changed formats. A verified preview is fenced against the fetched rates and the current catalog. Applies share the catalog lock with `price_add` and commit each entry with its audit record.

- [`analyticsQuery`](./analytics.go) serves `analytics_query` and shared leaf-only resource rollups (`taskResourceRollup`, `sessionResourceRollup`, `boundaryResourcesMap`, `definitionUsageResources`, `projectResources`), keeping PostgreSQL RLS active, resolving per-leaf prices via `LATERAL` before grouping, and keeping multi-currency `(currency, basis)` `CostFigure[]` entries separated. Fleet's own calls (`execution.system_actor`, set by [`connRecord`](./connections.go) for a coordinator read token from [`readTokenFor`](./github.go); [`systemReadsCleanup`](./system_activity.go) deletes the rows migration 69 marked once no spool line names them) stay out of `analytics_query`, `executions_list`, `projectResources`, prepared contributions and person/project budgets unless a request asks with `system: include|only`; connection budgets and Runners count them ([system activity](../../docs/designs/fleet-analytics.md#system-activity)).

- [`work_kit.go`](work_kit.go) runs every retried item queue (docs/designs/fleet-standard.md S6). A queue registers itself (`kitRegister`, from its file's `init`) with a name, a period, an optional switch, a due selection at the kit's clock `$now`, a step, optional cohorts and its retry table; the running kit passes each queue every period and at once on a `fleet_work` notification whose payload names it (one listener). Each step runs in one transaction with its retry reset; a failed cohort is retried in halves down to single steps (`kitBisect`). A failed step is one guarded write: `attempts` + 1, `next_attempt_at` at base x 2^attempts plus up to half a step of seeded jitter, never above the maximum (`FLEET_WORK_RETRY_BASE_MS` 100, `FLEET_WORK_RETRY_MAX_MS` 300000), and `last_error`, applied only while what the selection saw is still there, so a failure after an uncertain COMMIT records nothing. A busy advisory lock skips the item for this pass. A queue whose own selection or failure write fails backs off as a whole; nothing per item is kept in memory. [`rules.go`](rules.go) reports `work-stalled` (`problem:work:stalled`) for a queue failing that often.
- [`resource_projection.go`](resource_projection.go) registers three queues, run only with `FLEET_RESOURCE_PROCESSOR=on` (startup default off), every 100 ms and on their wakes: `resource-build` (a configured project without a build row is due too), `resource-repair` and `resource-work` (at most 100 due executions per pass; executions with a clearing scope yield; same-project executions run as cohorts). An execution is one item: all its rows share the attempts and pause. Source capture wakes `resource-work`, metadata capture `resource-repair`. [`rules.go`](rules.go) reports `resource-failing` (`problem:resource:failing`) for items at `kitFailingAttempts()`. [`resource_states.go`](resource_states.go) owns the state machines through typed queries ([`queries/resource_states.sql`](queries/resource_states.sql)): `buildTransition` (clearing, scanning, draining, ready; a rebuild restarts clearing) and `repairTransition` (enumerating, done, deleted). Design rules and their checks: [DESIGN_RULES.md](DESIGN_RULES.md) ([publication contract](../../docs/designs/fleet-analytics.md#publication-contract)).
- [`wake_outbox.go`](wake_outbox.go) always dispatches durable notification intents, independently of resource flags. `fleet_change` comes from canonical change/artifact/summary triggers and people replacement; `fleet_work` (payload: the queue name) comes from source/metadata capture; `fleet_resource_summary` retains internal project publication payloads. Producers append immutable UUID/source-XID/channel/payload intents in the source transaction. A bounded1000-row `SKIP LOCKED` claim, coalesced `pg_notify` and deletion of only claimed UUIDs commit atomically. Rollback/restart retain intents; listeners still recover from the original durable rows and XID barriers. Full batches continue immediately and idle recovery checks run every100ms. This removes PostgreSQL NOTIFY's global commit lock from canonical source transactions without disabling notifications or source capture ([protocol](../../docs/designs/fleet-analytics.md#durable-notification-delivery)).

### Internal prepared-resource interfaces

| Helper | Contract |
|---|---|
| `resourceReplace(ctx, app, executionID)` | One work step as a pass runs it, waiting for its locks: claim immutable work UUIDs due at the kit clock, read source/old contribution/frozen method in one SQL snapshot, check sorted project-then-execution locks, subtract/add support, publish header/revision and delete only claims atomically. A scope the hint did not know runs the step again (at most three times); any other failure is written by the kit. An ownership mismatch is recorded and its totals repaired in the failure's transaction (`resourceRepairOwnership`, parent row first). Source rows are never locked. |
| `resourceReplaceBatch(ctx, app, executionIDs)` | One cohort attempt (`resourceReplaceBatchStep`): at most 100 confidently same-project leaves, complete canonical lock set before authoritative per-leaf claims/snapshots, independent valuation/support changes and one project publication. Any SQL/scope failure rolls the cohort back; the kit retries it in halves. |
| `resourceBuildPage(ctx, app, projectID)` | One build step (`buildTransition`): one atomic page/checkpoint, at most 100 source IDs; clearing/scanning/draining/ready. Finalization requires no pending scoped work or unresolved metadata coverage in its snapshot. |
| `resourceRebuild(ctx, app, projectID)` | Internal maintenance: `buildTransition` starts clearing with a new generation and preparing epoch, and the kit restarts the build's retries in the same transaction (`restart`); retains all source work and frozen valuations. Ordinary replacements yield for every affected clearing scope. |
| `resourceMetadataPage(ctx, app, repairID)` | One repair step (`repairTransition`): atomic union scan of normalized old/new connection names and full account IDs; keeps repair scopes until enumeration and all seeded work drain. |
| `resourceReadPrepared(request, projectID)` | Call only after project authorization in a scoped `Store` read transaction. Reads the RLS-visible header/version, then maintenance-only progress through `unscoped`; both use the same repeatable-read snapshot. Missing projection is preparing. No source history, rebuild or expensive fallback. |
| `resourcePreparedHeader(request, projectID)` | Internal publication reducer over fixed metric/basis support, indexed extrema and maintained item counts; never enumerates tools, costs, prices or execution history. |

`ResourceContributionV1`, frozen `ResourceMethodV1` and `PreparedHeaderV1` derive from `contracts/ops-tasks.schema.json`. Money and credits stay exact decimal strings/PostgreSQL numeric internally; only the established header wire credits field converts to a number. A preparing contribution does not freeze a valuation before confirmed usage/time/model or a connection amount is available; the first eligible missing rate remains frozen. Support retains every tool and price reference. Version is `epoch:revision`, with revision retained as decimal text by the read seam; it is not source progress.

The initial sorted project-scope hint is one indexed maintenance read, without a separate read transaction; it is never authoritative. The cohort hint query materializes selected execution IDs, retained work IDs and matching captured scopes, then groups their canonical/totals/contribution/work union. Empty-queue statistics cannot turn the captured-scope lookup into one queue scan per selected leaf. Empty candidate lists do no database work. Internal scope-hint spans record candidate/returned counts and separate pool acquisition from query/decoding time without listing payloads or work UUIDs. Authoritative replacement spans record the actual number of claimed work UUIDs only after a successful claim read. The locked replacement claims due immutable work UUIDs and reads the source/frozen contribution/scopes in one statement snapshot, then verifies every observed scope before support writes. Existing build/summary rows use one joined phase check and summary lock; missing rows retain the initializer path. Scope expansion rolls back the whole transaction. Cohorts establish every leaf/project lock before claiming and do not expand locks in place; moving/NULL/multi-project or uncertain scopes use independent replacement. A failed cohort is not retried indefinitely as a cohort: its retained work returns to independent isolation/backoff, preserving project/metadata fairness and resolving uncertain COMMIT from durable state.

Support changes of every leaf in a replacement transaction are netted per project ([`resource_apply.go`](resource_apply.go)) and sent as one `pgx.Batch`: per table, an upsert for keys whose every component only grows, a delete for keys whose references reach zero and an update for the rest (CHECK constraints apply to an INSERT's proposed row before ON CONFLICT, so a losing key never takes the insert path). A cost key is netted only when the transaction only adds known amounts to it; any unknown amount or subtract keeps its per-contribution statements in order (inside the same batch), because a NULL value absorbs later sums until its row is deleted at the last reference and recreated. On a consistent ledger the result equals sequential per-contribution application (cost values keep numeric's scale, which cost items return as stored; metric sums may be stored trimmed, and every metric reader normalizes them) (a randomized PostgreSQL test compares both write paths with an independent simulation). Netting can no longer detect every corrupt-ledger case a lone subtract did: a missing row whose subtract and add cancel passes. A key whose net change is zero is not rewritten; `resource_reasons_merge` drops zero reason counts and rejects negative ones. An absent, unexpected metric without a missing reason has no support delta; measured zero, expected missing values and retained reasons still mutate support. A zero numeric amount never suppresses presence, expectation or reference changes. Tool/cost/price item-count updates occur only when the first support reference appears or the last disappears; calls, errors, exact amounts and reference multiplicities still change on every applicable contribution. Reading every batch result and closing it propagates every SQL error before replacement proceeds. The enclosing replacement transaction owns claims, authoritative per-leaf snapshots, the complete sorted lock set, exact support, contributions, publication and claim deletion. A SQL batch failure rolls the whole replacement transaction back. A confidently same-project cohort may contain up to 100 leaves and publish once; every leaf still retains its own frozen method and exact support. No concurrent project writer is introduced, and no source fact is considered consumed before confirmed COMMIT.

The three independent fixed-header reads use one ordered batch under the same project lock. Every result is consumed and a late SQL error aborts the replacement before publication.

`resourcePublish` updates the header/revision and appends an internal `fleet_resource_summary` wake intent atomically in one SQL statement. The revision trigger atomically appends project-filtered `resource_summary` changes to the existing XID/SSE transport; the always-on dispatcher emits their committed hints separately. `projects.go` owns the additive typed `project_detail`, `project_resources` and `project_resource_items` reads and startup `FLEET_RESOURCE_READS` flag (default off): disabled operations are unadvertised and return 503. The configuration reader is independent of stored header/progress and bounded C-order keyset pages; cursors bind epoch/scope/filter/position rather than publication revision. Large admitted tool tuples use stdlib zlib/base64url cursor v2 and typed packed tool positions; cursor v1 remains readable, and clients use optional item.position for large re-anchors within the unchanged HTTP body bound. Legacy `project_context` keeps its history query and live tariff selection. `resource.process`/`resource.replace` spans record duration, lock time, candidate count, fact size, failures and oldest pending age; source observation time remains unknown where not retained. Internal `resource.apply` spans (one per replacement transaction and project, carrying `apply_statements`) and `resource.publish` spans expose support/header write durations. Replacement records claim/snapshot return and confirmed transaction return timestamps. A `resource.batch` span owns a cohort transaction; per-leaf replacement spans share its confirmed commit endpoint and publication version, so their overlapping durations must not be summed as transaction wall time; publication-version metadata describes the SQL result until the enclosing transaction is confirmed. Successful prepared-read spans record only the returned version/state and project identifier, without row content.

## Invariants

- [Conversations controls](../../docs/designs/fleet-conversations.md#controls) use `threads.go` to resolve the composer destination under the request's session and project visibility. `agent_turn.go` reconciles the original message receipt before checking the target of a new submission.

- Pipeline steps persist their observed terminal `finishedAt` as `ended_at`; nonterminal/reopened steps clear it. Typed execution reads recover only valid retained terminal millisecond ends for older rows, without a database backfill or inference from duration/current time. Missing or malformed legacy timing stays unavailable. Pipeline containers remain excluded from leaf resource totals; reused-prefix timing keeps its original provenance.

- [`accounts.go`](accounts.go) couples account-host connectivity to the actual inspection destination: a fresh eligible native execution host takes precedence, a configured inspector remains the permitted fallback, and observations must match the configured holder. Discovery inspects an existing registry without authenticating or moving credentials.

- [`execution_trace.go`](execution_trace.go) retains originating trace metadata in execution/queued-message records, records one durable dispatch edge per command, and supplies optional command run attribution; `telemetry_trace` resolves execution IDs under PostgreSQL RLS before querying spans.

- The service requires `FLEET_PEOPLE_FILE` and `FLEET_DATABASE_URL`; [`setPeople`](./main.go) requires exactly one owner and rejects duplicate people or conflicting service-token common names.
- HTTP request headers, bodies and idle connections have 10 s, 30 s and 90 s timeouts; streaming responses have no global write timeout.
- [`readBody`](./main.go) limits JSON request bodies to 1 MiB and host calls cannot name another `hostId`. Host requests carry no person identity.
- [`Store.Read` and `Store.Write`](./tx.go) (over [`Store.txLocks`](./store.go)) use separate explicitly sized 16-connection read and write pools and give reads a repeatable-read snapshot; writes serialize in PostgreSQL via deduplicated, canonical-rank-sorted 64-bit `pg_advisory_xact_lock(hashtextextended(..., 0))` across `GLOBAL < dispatch < project:* < task:* < session:* < experiment:* < execution:* < host:* < usageKey:* < person-setting:* < budget:* < problems:*`, reject out-of-order lock acquisition, and retry serialization failures and deadlocks.
- Migration 67 adds a restrictive SELECT policy `live` to every project-owned table but the change feed and the resource tables: tombstoned rows and every row of a deleted project are invisible to every reader, the owner and the coordinator's own passes included, unless the transaction sets `fleet.deleted=on`. Only the executor-internal host routes set it (`deletedHostRoutes`: poll, receipts, events, spans; [`authorize`](./main.go), `showDeletedKey`), so the stop and teardown of deleted work are still delivered and their results land; every other host route (agent tools, project operations, child runs, artifact reads and transfers) reads as everyone does; delete and purge set it themselves.
- [`schema/policies.sql`](./schema/policies.sql) enables row-level security on project-owned state; every `project_scope` policy tests a row's project with `fleet_visible(project_id)` (migration 75), an inlined SQL function, plus its own extra terms. [`scopeOf`](./main.go) and [`refreshRequestAccess`](./project_access.go) set the transaction's project/person scope; the owner uses the unrestricted scope.
- [`schema/triggers.sql`](./schema/triggers.sql) source triggers retain transactional `resource_work` and non-secret `resource_metadata_repair` for prepared summaries. Work identities never cascade with source deletion; maintenance tables use FORCE RLS. Parent execution ownership aligns totals atomically, including NULL; totals writers lock the parent first. A projectless execution has `project_id` NULL, never `''` (check `execution_project_id_not_empty`, migration 68): every resource scope becomes a `project:<id>` lock. The opt-in [`resource_projection.go`](resource_projection.go) processor maintains replaceable contributions, fixed-size headers and normalized support; prepared public reads require startup exposure and current project authorization ([contract](../../docs/designs/fleet-analytics.md#prepared-project-resources)).
- [`migrate`](./store.go) applies each `-- migration N` schema section once under the migration lock, then `applySchemaFiles` runs each `schema/*.sql` file whose hash `schema_file` does not record yet, in one transaction under the same lock (an unchanged file is not run again, so a start takes no table lock). The files are the migrated database's deparsed definitions: `TestMigrationSchemaFiles` fails when they differ from it (`FLEET_UPDATE_SCHEMA_FILES=1` rewrites them after an edit).
- [`definitionState`](./definitions.go) computes definition state from stored revisions and shipped repository content; [`reconcileDefinitions`](./definitions.go) records shipped content but does not move an edited head.
- [`taskTransition`](./tasks.go) enforces declared task transitions; [`artifactCopyTransition` and `storeTransition`](./artifact_states.go) own `artifact_copy.state` and `store.state`. [`artifactGate`](./executions.go) keeps an execution waiting until required artifacts satisfy the completion requirement. The storage callback rechecks artifact requirements in the settlement transaction. [Artifact wait reconciliation](./placement.go) recovers missed callbacks at startup and on a separate tick.
- [`newS3`](./s3.go) refuses redirects for signed object-store requests; [`S3.send`](./s3.go) retries only selected transient statuses, throttling codes and network failures, up to three attempts.

## Side Effects

- Starts a loopback HTTP server, PostgreSQL listener and periodic passes through [`startAll`](./registry.go); writes telemetry through [`startTelemetry`](./telemetry.go).
- Mutates PostgreSQL state, emits `fleet_change` notifications, and may queue host commands. [`afterCommit` and `afterRollback`](./tx.go) delay registered outside effects until a transaction commits or rolls back.
- Reads people, release/configuration and Lab files; [`connections.go`](./connections.go) can ingest gateway spool files and remove fully imported past-day files only after commit. A gateway call becomes one `tool_run`. A download or resumable upload commit completes its existing row through `connComplete`. Upload completion applies provider usage and key effects once. A completion with no started row can create its own row. `connections_set_limits` (holder or owner) stores a connection's file limits and republishes the snapshot.
- Reads, writes, copies and deletes S3-compatible objects through [`S3`](./s3.go). Artifact deletion and retention routines keep tombstones and avoid deletion while a verified copy is unreachable.
- [`runChecks`](./lab.go) executes approved Lab check commands in a temporary directory; on Unix it kills the check process group after completion or cancellation.

## Verification

- Run: `cd go && go test ./coordinator`. Its PostgreSQL tests never pass by skipping unnoticed ([`pg_fixture_test.go`](pg_fixture_test.go)): the local ones start their own server (initdb with a UTF-8 locale, so no `LANG` is needed), and the fixture halves of outside tests (`TestResourcePostgres` and the like, which read a database URL from `tests/go/*.test.ts`) run their owner file through `tests/go/run-files.ts` when started directly (about 40 s, needs `node`). A test that cannot run here skips with its reason; `FLEET_REQUIRE_PG=1` makes it fail, `FLEET_PG_FIXTURES=outside` skips the fixture halves where the outside tests run anyway (CI's unit part, the merge gate below).
- Design rules ([DESIGN_RULES.md](DESIGN_RULES.md)): `TestDesign*` scan the source; `TestLaw` checks the resource laws on cloned databases (`FLEET_LAW_SEEDS` soaks, `FLEET_LAW_SEED` replays one); `TestLawMutants` requires a law to kill every planted defect in `testdata/mutants`.
- Build the executable: `cd go && CGO_ENABLED=0 go build -o bin/fleet-coordinator ./coordinator`
- For the repository-selected full gate, use the command in [`../../fleet.md`](../../fleet.md#verification); it requires the project test environment and is not a coordinator-only check.

## Finite pipeline plans

`pipeline_condition.go` owns the closed Boolean/enum grammar. `pipeline_plan.go` owns version-1 plan identity, revision fencing, selected execution references, current authority/handoff and canonical result/input bindings. `pipelines.go` compiles static v2 and conditional v3 definitions into that one model and projects internal observations from selected rows. Public plan reads do not reconstruct omitted work from generic execution lists. Old runtime formats require a clean start, without an adapter or state reset in source delivery.

`lab_assessment.go` captures fixed contained assessment bytes, materializes ordinary artifacts outside write locks and links exact evaluator/input/trial identities with the existing Lab score transaction. `lab_retry.go` verifies current-format selected command/process and artifact proof; missing proof conflicts and never authorizes provider replay.
