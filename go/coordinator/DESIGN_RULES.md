# Coordinator design rules

The checked form of [Fleet standard](../../docs/designs/fleet-standard.md) S1–S10. [`design_rules_test.go`](design_rules_test.go) (`TestDesignRules`) parses every non-test, non-generated Go file of this package. A file listed in its `designRulesLegacy` allowlist may still break the named rules; any other file fails. An allowlisted file that no longer breaks its rule also fails until its entry is removed, so the list only shrinks. `designRulesOwned` names the file that owns what a rule keeps out of every other file, with the reason (the work kit owns its loop and the retry-column writes); those entries stay.

The work kit ([`work_kit.go`](work_kit.go)) runs every retried item queue: a queue registers itself (`kitRegister`) with its period, selection, step and retry table; the kit runs each step in one transaction, writes a failure as one guarded statement into the row's `attempts`, `next_attempt_at` and `last_error`, and keeps nothing per item in memory. Work outside the database (a provider call, object I/O) is a `Call` the step leaves on its claim: the kit runs it after the step commits, outside any transaction, and then the step again with its `Result`, which that transaction records; what a crash between them leaves is the queue's to read from what it committed before the call. Owners move their items only through the kit: `kitSchedule` (due at a time, retries afresh), `kitWake` (a producer's new work, in its transaction) and `kitNotify` (a new row). Each lane (a queue name up to its first `-`) is passed by its own loop, one pass at a time; a queue without `Batch` may run up to `Workers` claims of a pass at once. One wake channel, `fleet_work`, carries the name of the queue with new work. The areas on the kit are named in `designKitAreas`: `resource_*.go`, and the queue files of pipeline runs and Lab experiments (`pipeline_work.go`; their steps are `pipelineWorkStep` in `pipelines.go` and `labWorkStep` in `lab.go`) and of delegation sources (`delegation_work.go`, step in `delegation.go`).

`TestLaw` ([`resource_laws_test.go`](resource_laws_test.go)) drives the real resource engine on cloned PostgreSQL databases with a seeded generator of source changes, faults (an error, a serialization failure, a terminated connection, a repeated poison), lost COMMIT responses, restarts, rebuilds and metadata repairs, and checks its laws after every pass and at quiescence: exactly one contribution per source execution matching its source and frozen method, no work left, support equal to the contributions replayed, headers equal to the independent rollup, pending iff scoped work or repairs exist, revisions growing within an epoch, `resource-failing` iff an item reached `kitFailingAttempts()`, bounded retries, frozen valuations. `FLEET_LAW_SEEDS=500` soaks; a violation prints the seed and its trace, `FLEET_LAW_SEED=<n>` replays it. The harness reaches the engine only through [`resource_laws_adapter_test.go`](resource_laws_adapter_test.go). `TestLawMutants` applies each planted defect of [`testdata/mutants`](testdata/mutants) with `go test -overlay` and requires a law to fail on it (M1 deletes a failed cohort's first execution's due work, M2 resets attempts on failure, M3 omits a moved contribution's subtraction); a mutant whose text no longer occurs fails as stale.

SQL is assembled at run time in one file, [`sql_builder.go`](sql_builder.go) (`designRulesOwned`, R-SQL): a resource item page (the item table a category names, its comparison and direction), `analytics_query` (the requested dimensions, filters and grouping), a list page with its counts and groups (tasks, sessions and the nav counters: the list's filter, group, sort and search) and a delete or purge cascade (the tables and columns of the reference map) have a shape that follows the request, which sqlc cannot express; their rows scan into typed structs (`typedRows`, [`tx.go`](tx.go)). Its identifiers and expressions come only from its Go allowlists, chosen by typed inputs; every request value is a bind parameter. Fixed statements stay in `queries/*.sql`, including the resource support writes, sent as one batch through `resourceBatch` (`resource_apply.go`); `taskLineageCTEs` stays there only for the accepted-result read in `tasks.go`.

| ID | Rule | Check |
|---|---|---|
| S1 | Every entity is a typed table with real columns and foreign keys; JSONB only in a `payload` column; `deleted_at` plus one `live` policy; visibility through `fleet_visible(project_id)`; functions, triggers and policies in idempotent files under `schema/`. | `TestMigrationSchemaFiles`: `schema/*.sql` is exactly the migrated database's functions, triggers, policies and row-level security switches, applied after the migrations (`applySchemaFiles`). Review: tables. |
| S2 | Queries only through sqlc from `queries/<area>.sql` into package `fleet/coordinator/db`; no SQL in Go, no `map[string]any` read from the database. | `R-SQL`: a string literal whose first word (after spaces and `(`) is `SELECT`, `INSERT`, `UPDATE`, `DELETE` or `WITH` in any case followed by more text, or upper case followed by a space. `R-MAP`: calls to `astr`, `anys`, `mapOf`, a `doc{...}` literal, the type `map[string]any` or `map[string]interface{}`. |
| S3 | Two transaction entry points, `store.Read` and `store.Write` with caller-declared entity locks; effects after commit only through `afterCommit`. | Review. Not built: a check for other entry points. |
| S4 | Operations fully declared in `contracts/ops-*.schema.json` (including `auth` and `agent`) and registered with one line `op("name", handler)`; one dispatcher `runOp`; 404 for invisible, 403 for a missing role; audit only through `audit(q, target, field, prev, next, extra)` with the actor from `actor()`. | `R-OP`: calls to `gatedOp`, `gatedObjOp`, `shaped`, `operation`, `agentTool`. `TestDesignOperationsDeclared`: every `contract.Operations` entry declares `auth`, `agent` and `description`. |
| S5 | Each state machine has one transition table and one `<x>Transition` function, the only writer of its state column. | `TestDesignStateWrites`: SQL literals, and calls of typed queries (`queries/*.sql`), writing a declared state column outside the owner file: the resource build, summary and metadata repair (`resource_states.go`), a host command's status (`commands.go`), `execution.state` (`execution_states.go`: `executionInsert`, `executionTransition`), `question.state` (`question_states.go`), `experiment.state` (`experiment_states.go`), `host.state` (`host_states.go`), `connection_key.state` (`key_states.go`), `question.cause` (`problems.go`), an `audit_log` row (`audit.go`: `audit()`, S4) and a kit queue's retry columns (`work_kit.go`). `TestDesignTransitions`: for the build, repair, command, execution, pipeline step (ended steps reopen), question, experiment, host (a removed host may be registered again; removed counts as its end) and connection key tables every state has a row, every target is a state, every state is reachable and reaches a terminal one. Task: `tasks.go`. |
| S6 | Retried item work only through the work kit; periodic passes only through `every()` or, for a pass that also runs on a wake channel or at start, `everyWake()` (`background.go`, which also runs coalesced after-commit effects); no goroutines, sleeps or tickers elsewhere except HTTP and stream plumbing; owner problems only through `problems.go`; wakes only through `wake_outbox` or `afterCommit`. | `R-GO`: `go` statements, `time.NewTicker`, `time.Tick`, `time.Sleep`, `time.AfterFunc` (the kit owns its loop). `TestDesignScheduling`: in the kit's areas no goroutine, ticker, timer, sleep, own connection, randomness, `every()` or statement clock. `TestDesignTransactions`: the kit's areas open no transaction. `TestLaw`, `TestLawMutants`: the resource engine's laws hold under faults and catch the planted defects. Owner problems: `TestDesignStateWrites` (`question.cause` only in `problems.go`). |
| S7 | Host protocol has a route map, a typed `Command` union and `Capability` enum; the executor has one outbox, HTTP client factory, outcome classifier, `supervise.Spawn` and goroutine helper. | Review (outside this package). |
| S8 | One `go/mcpserve` package serves every MCP server. | Review: the coordinator's `/api/tools`, `/api/project-tools` and `/api/hosts/agent-tools` serve through it; the executor's servers are stage 9. |
| S9 | App data only through `useOp(name, request)` and `useListPage`; closed contract row types; one JSON source for presets, view grammar and harness lists. | Review (outside this package). |
| S10 | These rules are checked by a source scan with a shrinking legacy allowlist, and this list is complete. | `TestDesignRules` in `go test ./coordinator`. `TestDesignRulesList`: every `TestDesign*` and `TestLaw*` is named here and every named check exists. |
