# Executor

## Overview

`executor` is the host-side Fleet binary. It polls and journals coordinator commands, starts and reconciles native harness processes, exposes scoped MCP services, manages project worktrees and artifacts, and reports receipts, events, readings, and spans.

## Interface

- The executable dispatches `mcp`, `qualify-mcp`, `mcp-guardian`, `code-shell`, `run-worker`, `reproject`, `selftest`, and `connection`; otherwise it runs the host executor loop or an owned MCP dependency command. The code-shell guardian ties a shell process group to its MCP server's lifetime pipe. `run-worker` supervises an individual run detached in its own session (`Setsid: true`) with `worker.sock`, `events.jsonl`, `exit.json`, `worker.lock`, and `<data>/active-releases/<ver>.lock`.
- `mcp connection <connection> <spec> [run file]` serves a connection's tools over stdio MCP; a spec tool with `file: upload` takes `{<path fields>, path}` and sends the local file, one with `file: download` saves the file and answers its path. `connection call <connection> <tool> [spec file]` makes one call with JSON arguments on stdin and prints its `CallLine` ([mcp_connection.go](mcp_connection.go), [fleet-connections.md §9](../../docs/designs/fleet-connections.md#9-files)).
- Command handling covers native harness sessions, scripts, project setup/teardown, account inspection and limit probes, artifact transfer, and host readiness.
- A command without `sessionId` (a host job, [fleet-conversations.md](../../docs/designs/fleet-conversations.md) migration step 2) runs under its `executionId`: its directory, launch row and sweep check use it, and a script gets an empty `FLEET_SESSION_ID` ([executor_events.go: `workID`](executor_events.go)).
- [`attachments.go`](attachments.go) `attachTurn`: a start payload's message attachments, already staged under `FLEET_INPUT_DIR/attachments/<execution>/` by `stageInputs`, are listed in the turn text with absolute path, type and size; Codex also gets each image as a `localImage` input, Claude the input folder as `--add-dir` ([Attachments](../../docs/designs/fleet-conversations.md#attachments)).
- `resolveAttemptContext` verifies and stages declared immutable instruction sources from local Git objects; `prepareInstructions` gives the resolved payload to the selected harness.
- Its stdio MCP servers (delegation, design rules, project forge, connection, code) serve through [`mcpserve.Stdio`](../mcpserve/README.md). `project-forge` (`forge.go`) exposes `publish_draft` and `delivery` (`status`, `code_review`, `ready`, `auto_merge`); `code_review` fences local and live PR heads, checks GitHub actor/push authority, verifies stored Fleet review evidence via the executor journal and `/api/hosts/forge/review`, posts the exact-SHA `code-review` commit status, and verifies readback; `ready` transitions drafts idempotently; `auto_merge` omits `--<method>` when the target base branch has a GitHub `merge_queue` rule; `status` includes `mergeQueueEntry` when present. Child processes start only through [`supervise.Spawn`](supervise/README.md), goroutines only through `errtrack.Go` (a panic is reported, then raised). HTTP clients come from `httpClient`/`streamClient` ([httpclient.go](httpclient.go)): redirects never followed, one pooled transport. [`design_rules_test.go`](design_rules_test.go) (`TestDesignRules`) mechanically enforces these S7/S10 boundaries (`E-MAP`, `E-PROC`, `E-GO`, `E-HTTP`) across non-test executor files against `designExecutorOwned`. A failed exchange or transfer step is classified once by `outcome` ([outbox.go](outbox.go)).
- The executor records command and process state in its SQLite journal and communicates with the coordinator through typed `contract` requests and events.
- `project-forge publish_draft` accepts an optional `force_with_lease` containing the expected remote commit as 40 lowercase hex characters. Git applies the lease to the session branch ref alone. The caller can read the remote PR head with `delivery status`.
- Call `ci_logs` on either publishing MCP server with `jobId` and `expectedHeadSha` to get job and failure metadata, error windows, a tail, and scan completeness. Window offsets point into the decoded, redacted `excerpt`. The job must be a GitHub Actions job with conclusion `failure` or a GitLab CI job with status `failed`. The repository grant, job branch and live branch head must match. This read requires the provider credential to have access to the job and its log.
- The [project-browser MCP](../../docs/configuration.md#coding-execution) exposes trusted keyboard and pointer input and returns redacted page summaries.

## Invariants

- Command trace context and run attribution are optional for mixed-version hosts. [`spans.go`](spans.go) restores the journaled command parent for a distinct terminal execution span; absent or invalid context starts a root with `missing.parent`. Harness/provider span ingestion remains a separate capability.

- Host secrets, account registries, credential homes, workspaces, Git metadata, and staged instruction sources are ownership-, path-, and symlink-checked before use ([executor_events.go: `hostSecret`](executor_events.go), [accounts.go: `runnable`](accounts.go), [attempt_context.go: `resolveAttemptContext`](attempt_context.go)).
- A launch is journaled before its process exists; owned process identities are journaled before reconciliation. After a restart (or an in-place `unix.Exec` upgrade of the poller), surviving detached `run-worker` processes holding `worker.lock` (or completed workers with `exit.json`) reattach cleanly into `e.live` without killing live runs; any launch without an active or cleanly exited worker is fenced and cleaned up ([executor_process.go: `launch`, `own`, `reconcileProcesses`](executor_process.go), [worker.go: `runWorker`](worker.go)).
- Host routes come from the contract: outbox rows through `queueTo(db, contract.Route<Name>, request)`, transfer calls through `transferReply(c, contract.Route<Name>, request)`, capabilities from `contract.CapabilityValues` and its prefixed helpers. A command is read as `contract.Command` (`typedCommand`, `run`); the journal keeps its JSON as received as its identity ([outbox.go](outbox.go), [executor_events.go: `typedCommand`](executor_events.go), [executor_launch.go: `run`](executor_launch.go)).
- JSON the executor reads (harness stream records, JSON-RPC frames, MCP arguments and replies, journal rows, registry and spec files) is decoded into structs one way, `typed[T]` / `typedRaw[T]` ([json.go](json.go)): keys match exactly (encoding/json alone matches field names case-insensitively), a value of another JSON type reads as absent, and open values (`jsonValue`) keep their decoded form; contract types whose error must surface decode strictly with `contractOf[T]`. The start payload's `project` is `contract.ProjectContext` and `agentConfig` is `contract.Profile`, decoded once per command. Harness records live in one file per harness (`harness_claude_records.go`, `harness_codex_records.go`, `harness_acp_records.go`, the shared envelope in `harness_records.go`). The MCP filter forwards the request value it checked, never the bytes it received, and refuses a request with a duplicate or case-variant key (`exactKeys`) ([mcp_filter.go](mcp_filter.go)). The map accessors `jStr`/`jObj`/`jBoolOr` are removed from non-test code (`harness_codex.go` uses typed `mcpServerEntry`, `mcp_code.go` uses `*codeCallError`) and forbidden by `E-MAP` in [`design_rules_test.go`](design_rules_test.go).
- A held coordinator poll (up to 25 s) does not pause the 100 ms process loop for live executions: exits, output, script deadlines and samples are handled while it waits. Each poll (`pollWait`) samples host CPU `load1`, `cpus`, and TTL-cached memory with swap, the macOS compressor, tmpfs `/tmp` and the top five memory consumers (`sampleHostLoad`, [host_consumers.go](host_consumers.go)) alongside `activeExecutions`, the release-managed CLI versions (`harnessVersions`) and the host tool versions (`toolVersions`: node, pnpm, gh, glab; the pin and the managed executable's version, or the PATH tool's with no pin while tool pins are off; each probed with `--version` once per changed file, [release_harnesses.go](release_harnesses.go)). A process-loop failure cancels the poll and stops the executor ([executor.go: `heldPoll`](executor.go)).
- A journaled request whose reply an MCP server waits for (delegation, agent tool, project request, artifact transfer) is answered through a FIFO under `<journal dir>/wake` named by its key: the server makes it (under a temporary name, renamed once open) before reading the journal, the executor signals it after writing the reply, and the server reads the journal on each signal and once at its deadline ([wake.go](wake.go)).
- Artifact transfers are journaled jobs in `transfers`, not outbox rows: an outbox row is one bounded coordinator request, a transfer is many steps with local and store I/O (reserve, parts, 32 MiB store PUTs, commit, loopback verify; a copy first downloads its whole source). The job's body (`transferJob`) journals each stored part, so a crash or retry resumes from the parts already done; the coordinator's artifact lease (1 h) is renewed by every parts request and every 10 minutes for queued or running uploads with a recorded reservation and for copy and verification commands; the command's final receipt (and an upload's artifact failure) is queued in the outbox in the same transaction that ends the job, so it never leaves before the transfer is done; MCP calls (artifact_save, artifact_get, artifact_list) read the row's response. Two lanes run one job each, oldest first, so a verification never waits behind a long upload or copy; a retried job uses the outbox's `backoff` ([upload.go](upload.go)).
- Spans leave through the outbox: once a minute `current.jsonl` is queued as batches of up to 1000 with a stable batch id ([spans.go: `queueSpans`](spans.go)); queued span batches do not hold an update drain, and a span batch's 429 or 503 holds only its own lane. Edge-held routes and retried rows share one backoff map (`holds`, `backoff`); a failed store part ends the transfer run, which retries with the job's backoff from its journaled parts (a journaled part resets the backoff) ([upload.go](upload.go)).
- Outbox rows of one execution share one lane, delivered in rowid order (a row without an execution is in its route's lane); lanes are delivered concurrently, so an agent tool, delegation or project request waits only behind its own execution's rows, and each execution's consecutive queued event rows go in one events request (up to 500 events; row by row after a timeout or a rejected batch). Rows without an execution are not ordered against execution rows. Each positive-wait agent `board_read` runs in its own lane so a matching post, an immediate read, or another waiting read can be delivered while it waits. A scan every 100 ms starts lanes that are not already delivering; edge answers inside a route's backoff count as one attempt ([outbox.go: `startFlush`, `edgeRedirect`](outbox.go)).
- Outbox rows are delivered with the held-poll deadline (`deliveryClient`, 35 s), not the 5 s heartbeat deadline: a coordinator ingest up to that bound is not cancelled and resent whole while the terminal receipt waits behind it. Beyond the bound the row is still cut and resent ([outbox.go: `flush`](outbox.go)).
- `board_read` adds the requested server wait (capped at 45 s) to the shared 20 s agent reply deadline in both direct MCP and Code Mode. The outbox allows 55 s for a board wait that needs more than its normal delivery allowance, and the direct Codex Fleet server allows 75 s when it exposes the tool. The MCP wrapper also carries the existing `project-env` timeout through to Codex. Code Mode can detach while the read is in progress and return the same job through `poll`. A pending reply identifies the original journal request for `agent_tool_result`.
- Agent tool and project operation attempts carry the execution trace. Their delivery spans record enqueue age, whether an earlier row of the same execution lane was queued at submission, HTTP outcome and time, and local receipt write and wake time when observed. An original MCP wait that expires emits separate pending evidence, including before any delivery attempt. The request correlation value is hashed. `agent_tool_result` only reads the retained journal entry and emits no delivery or wait span ([spans.go](spans.go), [mcp_delegation.go](mcp_delegation.go)).
- The launch queues its lifecycle receipt. Native events queue an additional `started` receipt on the first nonempty session identity and on identity changes. Repeated identities leave consecutive events available for batching ([executor_process.go: `tickOne`](executor_process.go)).
- A 2xx answer whose body is cut while it is read (a deadline, or a heartbeat poll cancelled when its exchange ends) is a transport retry; other statuses keep their class. A cancelled heartbeat poll writes no update signal. Only a complete 2xx answer that is not JSON is an edge condition; its log line names the status, content type, length and first 120 bytes ([outbox.go: `classify`](outbox.go)).
- A process or provider action with uncertain external outcome stays `unknown`; it is not silently retried as a known failure ([executor_process.go: `reconcile`](executor_process.go), [mcp_connection.go: `connectionCall`](mcp_connection.go)).
- An upload reads no byte before the path guard passes: one regular file with a single link, opened from `/` one component at a time with `O_NOFOLLOW`, every opened folder and the file matched by device and inode against the credential denylist (run file and its folder, Fleet token and Access files, the executor data folder's journal, run files, spool and registry copy, the host secret, the Git connection directory, forge, artifact-store and browser credential files the executor names, `~/.config/fleet`, `~/.local/share/fleet/gateway`, `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.netrc`, `~/.config/gh`, `~/.hermes/.env`, `~/Library/Keychains`, Claude and Codex logins; in a run also the executor user's home, its stores and every registry account's login folders, named in the run file) and inside `FLEET_FILES_ROOTS` when set (and the code sandbox's read roots for a bridged upload); a file holding the caller's bearer or Access secret is refused before any request ([file_guard.go](file_guard.go)). Downloads land in `FLEET_INPUT_DIR/attachments` in a run, else `FLEET_FILES_OUT` (default `~/.local/share/fleet/files`). The run file carries `FLEET_WORK_DIR`, `FLEET_INPUT_DIR`, `FLEET_USER_HOME` and `FLEET_RUN_DENY`; `tools/list` hides the spec's `file` and `idempotent`. Calls are served concurrently, so a long transfer never holds a ping or another call.
- Source resolution does not fetch, read working-tree rules, or execute Git hooks or filters. It requires the declared commit, exact blobs, digests, origin identity, and allowed owned storage ([attempt_context.go: `resolveAttemptContext`](attempt_context.go)).
- The Fleet MCP server's context (the director's operations with schemas) is written to `runs/<execution>.fleet.json` in the executor's private data directory (removed with the run's other files) and passed as `@path`, never in argv: Linux refuses one argument over 128 KiB ([mcp_delegation.go: `delegationServer`](mcp_delegation.go)).
- Every harness and script process carries the run marker (`FLEET_EXECUTION_ID`, `FLEET_EXECUTION_OWNER` = the data directory) and `TMPDIR=<data>/run-tmp/<execution>`. At run end the marked processes of that run that escaped the owned tree are killed (SIGTERM, then SIGKILL; their SysV shared memory removed) and counted in the execution span's `fleet.orphans`; at start, after `reconcileProcesses`, so are those of every run that is not unresolved, with their run TMPDIRs. Every hour (first right after `reconcile`) it removes session directories that hold no `worktree*` (also under `workspaces/*`), have no open command or journaled launch and are unchanged for `FLEET_TMP_SWEEP_AGE_HOURS` (24); with `FLEET_TMP_SWEEP=owned` the same pass removes entries of `/tmp` its user owns that are unchanged for that age and hold no socket. A pass that removed something writes a `host.cleanup` span. `mcp connection` exits when its parent changes or its release's executable is gone ([cleanup.go](cleanup.go), [fleet-host-cleanup.md](../../docs/designs/fleet-host-cleanup.md)).
- Worktree cleanup keeps work when configured reasons such as uncommitted changes, unpushed commits, or teardown failure apply ([worktree.go: `teardown`](worktree.go)).
- A start with `branch: false` gets a worktree detached at its base, with no session branch ([worktree.go: `worktree`](worktree.go)); a start with `readOnly: true` runs codex in its read-only sandbox, claude with Read, Glob and Grep only, and ACP agents in plan mode; the executor reports `start-access-v1`, so the coordinator places such starts only here ([harness_codex.go](harness_codex.go), [harness_command.go: `readOnlyTools`](harness_command.go), [harness_acp.go](harness_acp.go)).

## Side effects

- Starts and stops native processes, creates and removes worktrees and MCP-owner directories, writes session files and a SQLite journal, and uploads artifacts ([executor_launch.go: `run`](executor_launch.go), [executor_process.go: `release`](executor_process.go), [worktree.go: `teardown`](worktree.go), [upload.go: `sendParts`, `spawnTransfers`](upload.go)).
- Samples owned process trees on a 100 ms loop via `observe()`, records harness tool/turn metrics, and emits `ExecutionResourceSummary` on `process.closed` without periodic `resource.observation` events ([executor_process.go: `tickOne`, `observe`](executor_process.go), [executor_events.go: `buildExecutionResourceSummary`](executor_events.go), [harness_blocks.go: `runMetrics`](harness_blocks.go)).
- Runs approved local Git, harness, project-script, browser, and account-limit commands; it queues coordinator receipts and events ([executor_events.go: `event`, `receipt`](executor_events.go), [accounts.go: `readLimits`](accounts.go)).
- Connection file tools read caller-named local files and write downloaded files under the run's input folder or `FLEET_FILES_OUT` ([mcp_connection.go](mcp_connection.go)).
- Readiness and account observation read host configuration and native CLI state without sending tokens or credential contents ([readiness.go: `readiness`](readiness.go), [accounts.go: `accountInspect`](accounts.go)). A ready binding's observation also carries the models its vendor CLI offers (codex `model/list`, Claude Code `initialize`), absent when the probe fails ([accounts.go: `probeModels`](accounts.go)).

## Verification

Run from `go/`:

```sh
go test ./executor
CGO_ENABLED=0 go build -o bin/fleet-executor ./executor
```

With the [project-browser runtime paths](../../docs/configuration.md#coding-execution) set, run `go test ./executor -run TestProjectBrowserTrustedInput -count=1` to verify trusted input against local fixture origins.
