# Release-managed components

The pin manifests of a Fleet release ([host updates](../../docs/designs/fleet-host-updates.md)): `Kinds` lists each kind with its file, cache directory and component names: agent CLIs (`CLIs`, `config/harness-pins.json`) and host tools (`Tools`, `config/tool-pins.json`). `Kind.Env` names the tools the executor passes in an environment variable instead of PATH (Playwright and Chromium for the project browser). Versions are `x.y.z`, or `w.x.y.z` for Chromium. `Kind.Read` loads and validates a kind for one platform; `Read` is `CLIs.Read`. `Kind.Pinned` and `Kind.PinnedIn` answer a pin file's enabled flag and versions per target as written, enabled or not and unchecked, for display (the coordinator's Changes and update history). A missing or disabled manifest leaves that kind with the host. `Asset` gives the updater and executor the same digest-addressed payload and executable paths. The package performs no downloads or launches.
